# @kbn/esql-scripts

Home for the ES|QL definition and documentation generation scripts, plus the shared
utilities they rely on.

This package has no public API; it is a dev-only collection of scripts.

## Layout

- `lib/` — internal helpers shared by the generators (clearing doc directives).
- `definitions/` — generate the ES|QL function, command and settings definitions consumed by
  `@kbn/esql-language`.
- `documentation/` — generate the inline ES|QL function and command docs consumed by
  `@kbn/language-documentation`.

## Input

The generators read the ES|QL language definitions from the
[`@elastic/esql-definitions`](https://www.npmjs.com/package/@elastic/esql-definitions) npm package
(published from [elastic/esql-js](https://github.com/elastic/esql-js)), which ships the definitions
generated by Elasticsearch as typed subpath exports (`/functions`, `/operators`, `/commands`,
`/settings`, `/inline-cast`, `/promql-functions`, `/promql-operators` and the matching `*-docs`
exports). No Elasticsearch checkout is needed.

The output is written back into the `@kbn/esql-language` and `@kbn/language-documentation` packages
and committed. The generators add the Kibana-specific parts on top of the package data: `i18n`
wrapping of descriptions, the locations where each function is available, autocomplete hints and
enrichments, and the name enums.

## Usage

```sh
# from this package directory
pnpm make:defs   # function/command/settings definitions
pnpm make:docs   # inline function/command documentation
```

Both commands run `eslint --fix` on the generated files afterwards. Run
`node scripts/i18n_check --fix` from the repository root when descriptions change.

## Updating the definitions

`@elastic/esql` and `@elastic/esql-definitions` are released together and must stay on the same
version in the root `package.json`, matching the `@elastic/esql` suite `catalog:` in
`pnpm-workspace.yaml`. To pick up a new release:

1. Bump both packages in the root `package.json` and the `catalog:` entries in `pnpm-workspace.yaml`
   to the same version, then run `node scripts/kbn bootstrap`.
2. Run `pnpm make:defs` and `pnpm make:docs` from this package directory.
3. Run `node scripts/i18n_check --fix` from the repository root and commit the result.

The `esql_generate_function_metadata` Buildkite job
(`.buildkite/scripts/steps/esql_generate_function_metadata.sh`) runs these steps weekly and
opens an "[ES|QL] Update function metadata" pull request when anything changed.
