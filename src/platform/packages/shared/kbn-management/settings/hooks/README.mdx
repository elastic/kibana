## `useEditableSettings`

Manages the state for a page that edits a fixed list of UI settings: the `FieldDefinition` for each setting, the unsaved changes, and saving them.

```tsx
import { useEditableSettings } from '@kbn/management-settings-hooks';

const {
  fields,
  isLoading,
  loadError,
  retry,
  unsavedChanges,
  handleFieldChange,
  cleanUnsavedChanges,
  saveAll,
  isSaving,
} = useEditableSettings({
  settingsKeys: [mySettingId],
  settingsClient: settings.client,
  metadataClient: settings.metadata,
  scope: 'namespace',
});

const onSave = async () => {
  const { requiresReload } = await saveAll();
  if (requiresReload) {
    window.location.reload();
  }
};
```

- `fields` contains only the requested settings that are registered, keyed by setting ID, and refreshes when one of them changes. It is empty until the setting definitions load.
- The setting definitions (name, description, options, etc.) are not part of the bootstrap payload, so the hook fetches them with `useSettingDefinitions`. The page must render the `isLoading` and `loadError` states, as described in the `@kbn/management-settings-application` README, and can offer `retry` as an action on the error.
- `saveAll` rejects with the combined error messages when any update fails. Showing toasts is up to the caller.

## `useSettingDefinitions`

Fetches the full setting definitions for a scope, for a page that builds its own fields from them.

```tsx
import { useSettingDefinitions } from '@kbn/management-settings-hooks';

const { definitions, isLoading, loadError, retry } = useSettingDefinitions({
  metadataClient: settings.metadata,
  scope: 'namespace',
});
```

- `definitions` is empty until the request succeeds. Merge it with the client's current values using `mergeSettingDefinitions` from `@kbn/management-settings-utilities`.
- `isLoading` is only true before the definitions first load. When they are fetched again, such as for a new `metadataClient`, the loaded definitions stay in place while the request is in flight, so a form built from them stays mounted with its unsaved changes. If that request fails, `definitions` is empty and `loadError` is set.
- `loadError` is the error from the latest request, and is cleared while `retry` fetches the definitions again.
- Pass `isEnabled: false` to skip the request, such as when the user can't see the scope.

## `SettingDefinitionsLoadError`

The error to render in place of a settings form when its definitions fail to load. It shows the error message and a "Try again" button that fetches the definitions again.

```tsx
import { SettingDefinitionsLoadError } from '@kbn/management-settings-hooks';

{loadError && (
  <SettingDefinitionsLoadError
    error={loadError}
    onRetry={retry}
    data-test-subj="mySettingsLoadError"
  />
)}
```

- The title defaults to "Unable to load settings". Pass `title` to name the page's settings instead.
- The page decides where the callout goes. Put it where the settings would appear.
