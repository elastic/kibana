# ES|QL Read Query Templates — Records, Timeline, Influencers, RCA

Use `ml.query_anomalies` and pass the ES|QL below in the `query` parameter for `.ml-*` system indices. Keep `?param` placeholders in the query and bind values in `params` (keys without `?`, e.g. `{ "job_id_pattern": "*", "min_score": 25 }`). Never call with an empty argument object — `query` is always required. Omit the `params` field entirely when the query has no placeholders.

Section titles (e.g. `ad_query_anomaly_records`) are labels for the query examples only — they are not tool arguments.

For **source-data** examples (`ad_rca_source_evidence`, `ad_search_log_category_examples`) use `platform.core.execute_esql` instead.

**Anomaly results source:** `FROM .ml-anomalies` (materialized view of `record` / `bucket` / `influencer`). Always copy these templates as written. `ml.query_anomalies` probes whether the view exists on the connected Elasticsearch cluster and, on older versions that do not have it, rewrites to `FROM .ml-anomalies-*`. Do not write the wildcard yourself for these result types.

**Time fields:** Filter anomaly time ranges on `timestamp` (the bucket time of the anomaly). Do not filter historical results on `` `event.ingested` `` — that is when the result document was written, so a batch job run today would miss the analysis window. Never use `@timestamp`. Filter `is_interim == false` when you want finalized results only.

**`causes` is not supported** on the materialized view. Use flattened entity fields (`by_field_*`, `over_field_*`, `partition_field_*`, `influencer_field_*`) plus `actual` / `typical` instead.

### Fields available on `.ml-anomalies`

The view unifies the per-result-type score columns into two columns. Use `score` / `initial_score` for all result types; do not use `record_score`, `anomaly_score`, `influencer_score`, `initial_record_score`, `initial_anomaly_score`, or `initial_influencer_score` — those do not exist on the view.

| Use | Fields |
| --- | --- |
| Filter | `job_id` (keyword), `result_type` (`bucket` \| `record` \| `influencer`), `timestamp` (date — use this for time ranges), `is_interim` (boolean). `` `event.ingested` `` is result-document ingest time, not the anomaly time. |
| Aggregate | `timestamp`, `score`, `initial_score` (all double except `timestamp`) |
| Result columns | All of the above, plus `bucket_span` (long), `function`, `function_description`, `field_name`, `by_field_name`, `by_field_value`, `over_field_name`, `over_field_value`, `partition_field_name`, `partition_field_value`, `influencer_field_name`, `influencer_field_value`, `detector_index`, `actual`, `typical`, `event_count`, `processing_time_ms` |

Do not `KEEP`, filter, or aggregate fields that are not listed (`causes`, `probability`, `multi_bucket_impact`, `anomaly_score_explanation.*`, and others). Those are unknown columns on the materialized view.

**On older Elasticsearch clusters** (without the view), `ml.query_anomalies` falls back to `FROM .ml-anomalies-*` and automatically injects `EVAL score = COALESCE(record_score, anomaly_score, influencer_score), initial_score = COALESCE(initial_record_score, ...)` so the same templates work unchanged.

## ad_query_anomaly_records

Search anomaly records by score threshold and time range. Use `job_id_pattern='*'` for cross-job search or an exact job ID for single-job drill-down.

**Parameters:** `job_id_pattern` (string, LIKE wildcards), `min_score` (number), `start_time` (ISO 8601), `end_time` (ISO 8601)

```esql
FROM .ml-anomalies
| WHERE result_type == "record"
  AND job_id LIKE ?job_id_pattern
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
| SORT score DESC
| LIMIT 50
| KEEP job_id, timestamp, is_interim, score, initial_score,
       function, function_description, field_name, actual, typical, detector_index, bucket_span,
       by_field_name, by_field_value, over_field_name, over_field_value,
       partition_field_name, partition_field_value
```

## ad_query_anomaly_timeline

Time-series summary of anomaly severity across jobs. Use for cross-job swimlanes and detecting anomaly storms.

**Parameters:** `job_id_pattern`, `min_score`, `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "bucket"
  AND job_id LIKE ?job_id_pattern
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
| STATS max_score = MAX(score),
        job_count = COUNT_DISTINCT(job_id),
        jobs = VALUES(job_id),
        composite_score = SUM(score),
        avg_score = AVG(score)
  BY timestamp
| SORT timestamp
```

## ad_query_influencers

Find the most unusual entities across all or selected jobs. When `job_count > 1`, entities appear as influencers in multiple jobs — prime RCA signal.

**Parameters:** `job_id_pattern`, `min_score`, `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "influencer"
  AND job_id LIKE ?job_id_pattern
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
| STATS total_score = SUM(score),
        job_count = COUNT_DISTINCT(job_id),
        jobs = VALUES(job_id),
        max_score = MAX(score)
  BY influencer_field_name, influencer_field_value
| SORT total_score DESC
| LIMIT 30
```

## ad_rca_blast_radius

Measure how widespread an issue is by counting distinct partitions/entities affected by a specific anomalous value.

**Parameters:** `anomalous_value` (string), `min_score`, `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "record"
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
  AND (by_field_value == ?anomalous_value
       OR over_field_value == ?anomalous_value
       OR partition_field_value == ?anomalous_value)
| STATS affected_partitions = COUNT_DISTINCT(partition_field_value),
        affected_jobs = COUNT_DISTINCT(job_id),
        total_anomalies = COUNT(*),
        max_score = MAX(score),
        time_span_hours = DATE_DIFF("hour", MIN(timestamp), MAX(timestamp))
  BY by_field_value
| SORT affected_partitions DESC
```

## ad_rca_correlation

Find temporally correlated anomalies across different jobs. Sort by timestamp to detect cascading failures (network → app → DB).

**Parameters:** `job_id_pattern`, `min_score`, `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "record"
  AND job_id LIKE ?job_id_pattern
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
| SORT timestamp ASC
| KEEP job_id, timestamp, score, initial_score,
       function, function_description, field_name, actual, typical, detector_index,
       by_field_name, by_field_value, partition_field_name, partition_field_value,
       over_field_name, over_field_value
| LIMIT 100
```

## ad_rca_cross_job_entity_match

Starting from a specific entity value, find all other jobs where that entity appears as anomalous — across all split field types.

**Parameters:** `entity_value` (string), `min_score`, `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "record"
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
  AND (partition_field_value == ?entity_value
       OR by_field_value == ?entity_value
       OR over_field_value == ?entity_value)
| STATS max_score = MAX(score),
        anomaly_count = COUNT(*),
        functions = VALUES(function),
        fields = VALUES(field_name),
        first_anomaly = MIN(timestamp),
        last_anomaly = MAX(timestamp)
  BY job_id
| SORT max_score DESC
```

## ad_rca_detector_fingerprint


## ad_rca_multi_job_entities

Find entities that are anomalous in multiple jobs simultaneously — the strongest root cause signal.

**Parameters:** `min_score`, `min_job_count` (number, use 2 for root cause candidates), `start_time`, `end_time`

```esql
FROM .ml-anomalies
| WHERE result_type == "record"
  AND score >= ?min_score
  AND timestamp >= ?start_time
  AND timestamp <= ?end_time
| STATS job_count = COUNT_DISTINCT(job_id),
        jobs = VALUES(job_id),
        max_score = MAX(score),
        total_records = COUNT(*),
        functions = VALUES(function),
        fields = VALUES(field_name)
  BY partition_field_value
| WHERE job_count >= ?min_job_count
| SORT job_count DESC, max_score DESC
| LIMIT 20
```

## ad_rca_source_evidence

After identifying an anomaly, retrieve raw source documents from the original data index.

**Parameters:** `source_index` (LIKE pattern, get from datafeed config), `start_time`, `end_time`

```esql
FROM * METADATA _index
| WHERE _index LIKE ?source_index
  AND @timestamp >= ?start_time
  AND @timestamp <= ?end_time
| SORT @timestamp DESC
| LIMIT 50
```
