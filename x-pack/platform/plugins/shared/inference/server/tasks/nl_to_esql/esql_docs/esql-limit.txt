# LIMIT

The `LIMIT` processing command limits the number of rows returned.

## Syntax

`LIMIT max_number_of_rows`

`LIMIT max_number_of_rows BY grouping_expr1[, ..., grouping_exprN]`

### Parameters

#### `max_number_of_rows`

The maximum number of rows to return. When `BY` is specified, the maximum number of rows to return per group.

#### `grouping_exprX`

Optional. An expression that outputs the values to group by.

## Examples

### Limit

Return the first five employees after sorting by employee number.

```esql
FROM employees
| SORT emp_no ASC
| LIMIT 5
```

### With groups

Return the highest-paid employee for each gender.

```esql
FROM employees
| SORT salary DESC
| LIMIT 1 BY gender
| KEEP first_name, last_name, salary, gender
```

first_name:keyword | last_name:keyword | salary:integer | gender:keyword
Otmar | Herbst | 74999 | M
Tzvetan | Zielinski | 74572 | F
Lillian | Haddadi | 73717 | null

### Group by multiple values

Return the highest-paid employee for each languages and gender combination.

```esql
FROM employees
| SORT salary DESC
| LIMIT 1 BY languages, gender
```

## Limitations

Queries do not return more than 10,000 rows, regardless of the `LIMIT` command’s value. This is a configurable upper limit.

To reduce the impact of this limit:

- Reduce the result set size by modifying the query to only return relevant data. Use `WHERE` to select a smaller subset of the data.
- Shift post-query processing into the query itself. Use `STATS` to aggregate data in the query.

The upper limit applies only to the number of rows output by the query, not to the number of documents processed. The query still runs on the full data set.

Filter rows where `field0` matches `"value"` and request up to 20,000 results, subject to the configured maximum result limit.

```esql
FROM index | WHERE field0 == "value" | LIMIT 20000
```

Calculate the average of `field1` grouped by `field2` and request up to 20,000 grouped results, subject to the configured maximum result limit.

```esql
FROM index | STATS AVG(field1) BY field2 | LIMIT 20000
```

Both queries return at most 10,000 rows, even if more rows are available.

The default and maximum limits can be changed using these dynamic cluster settings:

- `esql.query.result_truncation_default_size`
- `esql.query.result_truncation_max_size`

For time-series queries that use the `TS` or `PROMQL` source commands, including requests to the PromQL HTTP API, the default and maximum limits are higher and can be changed using these cluster settings:

- `esql.query.timeseries_result_truncation_default_size`
- `esql.query.timeseries_result_truncation_max_size`

Increasing these values can increase memory pressure, processing time, and internode traffic within and across clusters.
