# MMR

The `MMR` command reduces a result set by applying a diversification strategy to the returned rows. It uses Maximum Marginal Relevance to discard rows that are too similar to each other while preserving the ordering of the input rows.

## Syntax

`MMR [query_vector] ON field LIMIT limit [WITH { "lambda": lambda_value }]`

### Parameters

#### field

The name of the field that will use its values for the diversification process. The field must be a `dense_vector` type.

#### limit

The maximum number of rows to return after diversification.

#### query_vector

Optional. The query vector to use as part of the diversification algorithm for comparison. It must have the same number of dimensions as the vector field you are searching against. It must be one of:

- An array of floats
- A hex-encoded byte vector, with one byte per dimension, or one byte per 8 dimensions for `bit`
- A base64-encoded vector string. Base64 supports `float` and `bfloat16` in big-endian format, `byte`, and `bit` encodings depending on the target field type
- A function or expression that returns a `dense_vector`

#### lambda_value

Required if `WITH` is used. A value between 0.0 and 1.0 that controls how similarity is calculated during diversification. Higher values weight similarity to the `query_vector` more heavily, while lower values weight diversity more heavily.

## Examples

Diversify ten sorted rows to return three rows using the `text_vector` field.

```esql
FROM mmr_text_vector_keyword
| SORT keyword_field
| LIMIT 10
| MMR ON text_vector LIMIT 3
| DROP text_vector, byte_vector, bit_vector
```

| keyword_field:keyword | text_body:text |
| --- | --- |
| test1 | first text |
| test3 | third text |
| test6 | sixth text |

Diversify ten sorted rows using an explicit query vector and a lambda value.

```esql
FROM mmr_text_vector_keyword
| SORT keyword_field
| LIMIT 10
| MMR [0.1, 0.2, 0.3] ON text_vector LIMIT 3 WITH { "lambda": 0.1 }
| DROP text_vector, byte_vector, bit_vector
```

| keyword_field:keyword | text_body:text |
| --- | --- |
| test3 | third text |
| test6 | sixth text |
| test8 | eighth text |

Generate a query vector with `TEXT_EMBEDDING`, run a vector search, and diversify the top results.

```esql
FROM dense_vector_text METADATA _score
| EVAL query_embedding = TEXT_EMBEDDING("be excellent to each other", "test_dense_inference")
| WHERE KNN(text_embedding_field, query_embedding)
| SORT _score DESC
| LIMIT 10
| MMR TEXT_EMBEDDING("be excellent to each other", "test_dense_inference") ON text_embedding_field LIMIT 3 WITH { "lambda": 0.2 }
| KEEP text_field, query_embedding
```

| text_field:text | query_embedding:dense_vector |
| --- | --- |
| be excellent to each other | [45.0, 55.0, 54.0] |
| live long and prosper | [45.0, 55.0, 54.0] |
| all we have to decide is what to do with the time that is given to us | [45.0, 55.0, 54.0] |

## Limitations

You must limit the number of input rows before the `MMR` command. For example, use the `LIMIT` command to restrict the input.

In a cross-cluster query, the inference endpoint used to generate a query vector must exist on the cluster that receives the query.
