# DEDUP

`DEDUP` removes duplicate rows from a result set, keeping only one row per unique combination of values across all columns.

`DEDUP` compares all columns currently in scope and discards any row that is an exact duplicate of a previously seen row. Null values are treated as equal for deduplication. A multivalued column is compared as a whole: two values are equal only if they hold the same values in the same order. `[a, b]`, `[b, a]`, and `[a, a, b]` are three different values, so `DEDUP` keeps a row for each of them.

After a `SORT`, the rows that `DEDUP` keeps stay in sort order, each at the position of its first occurrence. Without a `SORT`, the output row order is not defined.

`DEDUP` is equivalent to `LIMIT 1 BY <all columns>`.

## Syntax

`DEDUP`

### Parameters

`DEDUP` takes no parameters.

## Examples

Remove duplicate values from a single column.

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10003, 10005, 10006)
| KEEP gender
| DEDUP
| SORT gender
```

gender:keyword
F
M

Remove rows that are duplicates across multiple columns.

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10010, 10011)
| KEEP gender, languages
| DEDUP
| SORT gender NULLS LAST, languages
```

gender:keyword | languages:integer
F | 5
M | 2
null | 4
null | 5

Keep up to two rows per unique `languages` value with `LIMIT 2 BY`.

```esql
FROM employees
| WHERE emp_no IN (10001, 10003, 10007, 10008, 10010)
| KEEP languages
| LIMIT 2 BY languages
| SORT languages
```

languages:integer
2
2
4
4

Deduplicate on `gender` while returning `first_name` and `last_name`.

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10003, 10005, 10006)
| SORT last_name
| LIMIT 1 BY gender
| KEEP first_name, last_name, gender
```

first_name:keyword | last_name:keyword | gender:keyword
Parto | Bamford | M
Anneke | Preusig | F

## Limitations

`DEDUP` cannot be used when any column in scope has one of the following types: `aggregate_metric_double`, counter fields (`counter_long`, `counter_integer`, `counter_double`), `date_range`, `exponential_histogram`, `tdigest`, `date_period`, or `time_duration`. Attempting to do so results in a validation error. Use `KEEP` or `DROP` before `DEDUP` to remove such columns.

Columns of an `unsupported` type are ignored when comparing rows, and `DEDUP` does not fail because of them. This includes fields mapped to incompatible types across the indices of a `FROM`: such a field is returned as `null` until it is converted, so it cannot tell rows apart. To deduplicate on the value of such a field, convert it first and then use `DEDUP`.

Full-text searches on indexed fields, such as `MATCH` or `KQL`, can't appear after `DEDUP` in the same pipeline.
