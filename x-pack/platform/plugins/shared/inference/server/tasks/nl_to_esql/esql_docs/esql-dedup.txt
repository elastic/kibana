# DEDUP

`DEDUP` removes duplicate rows from a result set, keeping only one row per unique combination of values across all columns. Null values are treated as equal for deduplication. `DEDUP` is equivalent to `LIMIT 1 BY <all columns>`.

## Syntax

`DEDUP`

### Parameters

`DEDUP` takes no parameters.

## Examples

Remove duplicate values from a single column:

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10003, 10005, 10006)
| KEEP gender
| DEDUP
| SORT gender
```

gender:keyword
F
M

Remove rows that are duplicates across multiple columns:

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10010, 10011)
| KEEP gender, languages
| DEDUP
| SORT gender NULLS LAST, languages
```

gender:keyword | languages:integer
F | 5
M | 2
null | 4
null | 5

Use `LIMIT 2 BY languages` to retain up to two rows per `languages` value:

```esql
FROM employees
| WHERE emp_no IN (10001, 10003, 10007, 10008, 10010)
| KEEP languages
| LIMIT 2 BY languages
| SORT languages
```

languages:integer
2
2
4
4

Use `SORT` and `LIMIT 1 BY gender` to keep one row per `gender` value while returning other columns:

```esql
FROM employees
| WHERE emp_no IN (10001, 10002, 10003, 10005, 10006)
| SORT last_name
| LIMIT 1 BY gender
| KEEP first_name, last_name, gender
```

first_name:keyword | last_name:keyword | gender:keyword
Parto | Bamford | M
Anneke | Preusig | F

## Limitations

`DEDUP` cannot be used when any column in scope has one of the following types: `aggregate_metric_double`, counter types (`counter_long`, `counter_integer`, `counter_double`), or `date_range`. Attempting to do so results in a validation error.

Columns of an `unsupported` type are ignored when comparing rows, and `DEDUP` does not fail because of them. This includes fields mapped to incompatible types across the indices of a `FROM` query. Such a field is returned as `null` until it is converted, so it cannot distinguish rows. For example, if `emp_no` is `integer` in one index and `long` in another, `FROM employees, employees_incompatible | KEEP emp_no | DEDUP` returns a single row. A later conversion such as `EVAL e = emp_no::long` does not bring the removed rows back. To deduplicate on the value of such a field, convert it first and then use `DEDUP`: `EVAL e = emp_no::long | DROP emp_no | DEDUP`.

Full-text search functions, such as `MATCH` or `KQL`, cannot appear after `DEDUP` in the same pipeline.
