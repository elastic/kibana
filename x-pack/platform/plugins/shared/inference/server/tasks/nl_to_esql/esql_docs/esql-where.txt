# WHERE

The `WHERE` processing command produces a table containing rows from the input table for which the provided condition evaluates to `true`.

## Syntax

`WHERE expression`

### Parameters

#### expression

A boolean expression.

## Examples

Filter employees where `still_hired` is `true`.

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired == true
```

Filter employees using a boolean field directly.

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired
```

Retrieve logs from the last hour using date math.

```esql
FROM sample_data
| WHERE @timestamp > NOW() - 1 hour
```

Filter employees by applying the `LENGTH` function to `first_name`.

```esql
FROM employees
| KEEP first_name, last_name, height
| WHERE LENGTH(first_name) < 4
```

Filter employees where `birth_date` is `NULL`.

```esql
FROM employees
| WHERE birth_date IS NULL
```

Filter employees where `is_rehired` is not `NULL`, then count `emp_no`.

```esql
FROM employees
| WHERE is_rehired IS NOT NULL
| STATS COUNT(emp_no)
```

Match books where `author` contains `Faulkner`.

```esql
FROM books
| WHERE MATCH(author, "Faulkner")
```

Match books where `title` contains all query terms, then keep `title`.

```esql
FROM books
| WHERE MATCH(title, "Hobbit Back Again", {"operator": "AND"})
| KEEP title;
```

Filter employees whose `first_name` matches a wildcard pattern with `LIKE`.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal `*` character in a string pattern.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character using triple-quoted strings.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows-style path with a wildcard pattern.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Filter rows using a list of `LIKE` patterns.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Filter employees with a `LIKE` pattern supplied through a query placeholder.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Filter employees with a `LIKE` pattern built from a constant expression.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose `first_name` matches a regular expression with `RLIKE`.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal `(` character in a regular expression.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character using triple-quoted strings.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Filter rows using a list of `RLIKE` patterns.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Filter employees with an `RLIKE` pattern supplied through a query placeholder.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Filter employees with an `RLIKE` pattern built from a constant expression.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Test whether an expression equals any value in a list with `IN`.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

## Limitations

In value exclusions, fields with `null` values are excluded from search results. In this context, `null` means either an explicit `null` value in the document or no value at all. For example, `WHERE field != "value"` is interpreted as `WHERE field != "value" AND field IS NOT NULL`.

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact indexed string.
