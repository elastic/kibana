# WHERE

The `WHERE` processing command produces a table that contains all rows from the input table for which the provided condition evaluates to `true`.

For value exclusions, fields with `null` values are excluded from search results. In this context, `null` means either an explicit `null` value in the document or no value at all. For example, `WHERE field != "value"` is interpreted as `WHERE field != "value" AND field IS NOT NULL`.

## Syntax

`WHERE expression`

### Parameters

#### expression

A boolean expression.

## Examples

Filter employees by the `still_hired` boolean field.

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired == true
```

Filter employees by the `still_hired` boolean field using the simplified boolean form.

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired
```

Retrieve rows from the last hour using date math and `NOW()`.

```esql
FROM sample_data
| WHERE @timestamp > NOW() - 1 hour
```

Filter employees by the character length of `first_name`.

```esql
FROM employees
| KEEP first_name, last_name, height
| WHERE LENGTH(first_name) < 4
```

Filter employees where `birth_date` is `NULL`.

```esql
FROM employees
| WHERE birth_date IS NULL
```

| first_name:keyword | last_name:keyword |
| --- | --- |
| Basil | Tramer |
| Florian | Syrotiuk |
| Lucien | Rosenbaum |

Count employees where `is_rehired` is not `NULL`.

```esql
FROM employees
| WHERE is_rehired IS NOT NULL
| STATS COUNT(emp_no)
```

| COUNT(emp_no):long |
| --- |
| 84 |

Filter books by matching `author` against `Faulkner`.

```esql
FROM books
| WHERE MATCH(author, "Faulkner")
```

| book_no:keyword | author:text |
| --- | --- |
| 2378 | [Carol Faulkner, Holly Byers Ochoa, Lucretia Mott] |
| 2713 | William Faulkner |
| 2847 | Colleen Faulkner |
| 2883 | William Faulkner |
| 3293 | Danny Faulkner |

Filter books by matching `title` with the `AND` operator.

```esql
FROM books
| WHERE MATCH(title, "Hobbit Back Again", {"operator": "AND"})
| KEEP title;
```

| title:text |
| --- |
| The Hobbit or There and Back Again |

Filter employees whose `first_name` matches a `LIKE` wildcard pattern.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

| first_name:keyword | last_name:keyword |
| --- | --- |
| Ebbe | Callaway |
| Eberhardt | Terkki |

Filter a row by matching a literal `*` character with `LIKE`.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Filter a row by matching a literal `*` character with `LIKE` and triple-quoted strings.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Filter a Windows-style path with `LIKE` and triple-quoted strings.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Filter a row by matching any pattern in a `LIKE` pattern list.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Filter employees with a `LIKE` pattern supplied through a REST query placeholder.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Filter employees with a `LIKE` pattern built from a constant expression.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose `first_name` matches an `RLIKE` regular expression.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

| first_name:keyword | last_name:keyword |
| --- | --- |
| Alejandro | McAlpine |

Filter a row by matching a literal `(` character with `RLIKE`.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Filter a row by matching a literal `(` character with `RLIKE` and triple-quoted strings.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Filter a row by matching any pattern in an `RLIKE` pattern list.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Filter employees with an `RLIKE` pattern supplied through a REST query placeholder.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Filter employees with an `RLIKE` pattern built from a constant expression.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Filter rows by testing whether `c-a` equals any element in an `IN` list.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

| a:integer | b:integer | c:integer |
| --- | --- | --- |
| 1 | 4 | 3 |

## Limitations

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact indexed string. To perform full-text search, use `MATCH` or `QSTR`.
