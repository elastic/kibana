# WHERE

The `WHERE` processing command produces a table that contains all rows from the input table for which the provided condition evaluates to `true`.

In value exclusions, fields with `null` values are excluded from search results. In this context, `null` means either an explicit `null` value in the document or no value at all. For example, `WHERE field != "value"` is interpreted as `WHERE field != "value" AND field IS NOT NULL`.

## Syntax

`WHERE expression`

### Parameters

#### expression

A boolean expression used to filter rows.

## Examples

Filter employees by the `still_hired` boolean field:

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired == true
```

Filter employees directly on the `still_hired` boolean field:

```esql
FROM employees
| KEEP first_name, last_name, still_hired
| WHERE still_hired
```

Retrieve logs from the last hour using date math:

```esql
FROM sample_data
| WHERE @timestamp > NOW() - 1 hour
```

Filter employees with first names shorter than four characters using `LENGTH`:

```esql
FROM employees
| KEEP first_name, last_name, height
| WHERE LENGTH(first_name) < 4
```

Filter employees with a `NULL` `birth_date` value:

```esql
FROM employees
| WHERE birth_date IS NULL
```

Count employees with a non-`NULL` `is_rehired` value:

```esql
FROM employees
| WHERE is_rehired IS NOT NULL
| STATS COUNT(emp_no)
```

Match books whose `author` field contains `Faulkner`:

```esql
FROM books
| WHERE MATCH(author, "Faulkner")
```

Match books whose `title` field contains all terms in `Hobbit Back Again`:

```esql
FROM books
| WHERE MATCH(title, "Hobbit Back Again", {"operator": "AND"})
| KEEP title;
```

Filter employees whose `first_name` matches a `LIKE` wildcard pattern:

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal `*` character in a string with `LIKE` escaping:

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character in a string with `LIKE` and triple-quoted strings:

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows-style path with `LIKE` and triple-quoted strings:

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Filter a row if `message` matches any pattern in a `LIKE` pattern list:

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Filter employees using a `LIKE` pattern supplied by a REST query placeholder:

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Filter employees using a `LIKE` pattern built from a constant expression:

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose `first_name` matches an `RLIKE` regular expression:

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal `(` character in a string with `RLIKE` escaping:

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character in a string with `RLIKE` and triple-quoted strings:

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Filter a row if `message` matches any pattern in an `RLIKE` pattern list:

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Filter employees using an `RLIKE` pattern supplied by a REST query placeholder:

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Filter employees using an `RLIKE` pattern built from a constant expression:

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Filter a row by testing whether an expression equals one of several values with `IN`:

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```
