# LOOKUP-JOIN

`LOOKUP JOIN` adds data from another index, called a lookup index, to query results. It adds new columns by finding documents in the lookup index that match rows in the current result table.

## Syntax

`FROM <source_index>
| LOOKUP JOIN <lookup_index> ON <join_condition>`

### Parameters

#### `<source_index>`

The source index used by the query.

#### `<lookup_index>`

The name of the lookup index. This must be a specific index name or alias. Wildcards and remote cluster prefixes are not supported. If the query source includes remote indices, the lookup index must exist on all involved clusters. Indices used for lookups must be configured with the `lookup` index mode.

In cross-cluster or cross-project queries, you can prefix the index name with `_coordinator:` to run the lookup on the coordinating node of the local cluster or origin project instead of on each remote cluster or linked project. This allows `LOOKUP JOIN` to be used after pipeline-breaking commands such as `STATS`, `LIMIT`, and `SORT`.

#### `<join_condition>`

The join condition used to match rows from the current query results with documents in the lookup index.

Can be one of the following:

- A single field name
- A comma-separated list of field names, for example `<field1>, <field2>, <field3>`
- An expression with one or more predicates linked by `AND`, for example `<left_field1> >= <lookup_field1> AND <left_field2> == <lookup_field2>`. Each predicate compares a field from the left index with a field from the lookup index using binary operators (`==`, `>=`, `<=`, `>`, `<`, `!=`). Each field name in the join condition must exist in only one of the indexes. Use `RENAME` to resolve naming conflicts.
- An expression that includes full text functions and other Lucene-pushable functions, for example `MATCH(<lookup_field>, "search term") AND <left_field> == <lookup_field>`. These functions can be combined with binary operators and logical operators (`AND`, `OR`, `NOT`) to create complex join conditions. At least one condition that relates the lookup index fields to the left side of the join fields is still required.

If using a join on a single field or a field list, the fields used must exist in both the current query results and in the lookup index. If the fields contain multi-valued entries, those entries will not match anything, and the added fields will contain `null` for those rows.

## Examples

Check source IPs against known malicious addresses.

```esql
FROM firewall_logs
| LOOKUP JOIN threat_list ON source.IP
```

Filter firewall logs to rows with a matching `threat_list` entry.

```esql
FROM firewall_logs
| LOOKUP JOIN threat_list ON source.IP
| WHERE threat_level IS NOT NULL
```

Pull environment and ownership details for each host in metrics data.

```esql
FROM system_metrics
| LOOKUP JOIN host_inventory ON host.name
| LOOKUP JOIN ownerships ON host.name
```

Show application logs with owning team or escalation information.

```esql
FROM app_logs
| LOOKUP JOIN service_owners ON service_id
```

Filter employee rows before joining with the language lookup index.

```esql
FROM employees
| EVAL language_code = languages
| WHERE emp_no >= 10091 AND emp_no < 10094
| LOOKUP JOIN languages_lookup ON language_code
```

emp_no:integer | language_code:integer | language_name:keyword
10091 | 3 | Spanish
10092 | 1 | English
10093 | 3 | Spanish

Filter employee rows after joining with the language lookup index.

```esql
FROM employees
| EVAL language_code = languages
| LOOKUP JOIN languages_lookup ON language_code
| WHERE emp_no >= 10091 AND emp_no < 10094
```

emp_no:integer | language_code:integer | language_name:keyword
10091 | 3 | Spanish
10092 | 1 | English
10093 | 3 | Spanish

## Limitations

`LOOKUP JOIN` has the following limitations:

- The lookup index must be a specific index name or alias.
- Wildcards and remote cluster prefixes are not supported for the lookup index.
- If the query source includes remote indices, the lookup index must exist on all involved clusters.
- Indices used for lookups must be configured with the `lookup` index mode.
- Joins on single fields or field lists require the fields to exist in both the current query results and the lookup index.
- Multi-valued join field entries do not match anything. The added fields contain `null` for those rows.
- Serverless Elasticsearch Vector Database projects do not support lookup indices.
