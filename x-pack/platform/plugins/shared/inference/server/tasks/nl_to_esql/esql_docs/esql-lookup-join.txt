# LOOKUP-JOIN

The `LOOKUP JOIN` command adds columns from a lookup index to query results by matching rows against documents in that index. When a row matches a lookup document on the join condition, fields from the lookup document are added to that row. Multiple lookup matches produce multiple output rows.

## Syntax

`FROM <source_index> | LOOKUP JOIN <lookup_index> ON <join_condition>`

### Parameters

#### `<lookup_index>`

The name of the lookup index. This must be a specific index name or alias. Wildcards and remote cluster prefixes are not supported. If the query source includes remote indices, the lookup index must exist on all involved clusters. Indices used for lookups must be configured with the `lookup` index mode. Applies to: Serverless Elasticsearch Vector Database projects: Unavailable.

In cross-cluster or cross-project queries, you can prefix the index name with `_coordinator:` to run the lookup on the coordinating node of the local cluster or origin project instead of on each remote cluster or linked project. This allows `LOOKUP JOIN` to be used after pipeline-breaking commands such as `STATS`, `LIMIT`, and `SORT`. Applies to: Elastic Stack: Planned. Applies to: Elastic Cloud Serverless: Generally available.

#### `<join_condition>`

Can be one of the following:

- A single field name
- A comma-separated list of field names, for example `<field1>, <field2>, <field3>`. Applies to: Elastic Stack: Generally available since 9.2.
- An expression with one or more predicates linked by `AND`, for example `<left_field1> >= <lookup_field1> AND <left_field2> == <lookup_field2>`. Each predicate compares a field from the left index with a field from the lookup index using binary operators (`==`, `>=`, `<=`, `>`, `<`, `!=`). Each field name in the join condition must exist in only one of the indexes. Use `RENAME` to resolve naming conflicts. Applies to: Elastic Stack: Preview since 9.2. Applies to: Elastic Cloud Serverless: Preview.
- An expression that includes full text functions and other Lucene-pushable functions, for example `MATCH(<lookup_field>, "search term") AND <left_field> == <lookup_field>`. These functions can be combined with binary operators and logical operators (`AND`, `OR`, `NOT`) to create complex join conditions. At least one condition that relates the lookup index fields to the left side of the join fields is still required. Applies to: Elastic Stack: Preview since 9.3. Applies to: Elastic Cloud Serverless: Preview.

If using a join on a single field or a field list, the fields used must exist in both the current query results and the lookup index. Join fields must use compatible types.

## Examples

Check source IPs against known malicious addresses and add matching threat details from the threat list.

```esql
FROM firewall_logs
| LOOKUP JOIN threat_list ON source.IP
```

Filter firewall logs to only rows with a matching threat list entry.

```esql
FROM firewall_logs
| LOOKUP JOIN threat_list ON source.IP
| WHERE threat_level IS NOT NULL
```

Pull host inventory and ownership details into system metrics.

```esql
FROM system_metrics
| LOOKUP JOIN host_inventory ON host.name
| LOOKUP JOIN ownerships ON host.name
```

Show application logs with service owner metadata.

```esql
FROM app_logs
| LOOKUP JOIN service_owners ON service_id
```

Filter employees before joining language metadata.

```esql
FROM employees
| EVAL language_code = languages
| WHERE emp_no >= 10091 AND emp_no < 10094
| LOOKUP JOIN languages_lookup ON language_code
```

emp_no:integer | language_code:integer | language_name:keyword
10091 | 3 | Spanish
10092 | 1 | English
10093 | 3 | Spanish

Filter employees after joining language metadata; the optimizer can push the filter before the lookup when possible.

```esql
FROM employees
| EVAL language_code = languages
| LOOKUP JOIN languages_lookup ON language_code
| WHERE emp_no >= 10091 AND emp_no < 10094
```

emp_no:integer | language_code:integer | language_name:keyword
10091 | 3 | Spanish
10092 | 1 | English
10093 | 3 | Spanish

## Limitations

- The lookup index must be a specific index name or alias. Wildcards and remote cluster prefixes are not supported.
- Indices used for lookups must be configured with the `lookup` index mode.
- `LOOKUP JOIN` is unavailable in Serverless Elasticsearch Vector Database projects.
- If the query source includes remote indices, the lookup index must exist on all involved clusters unless `_coordinator:` is used in supported environments.
- For single-field or field-list joins, the join fields must exist in both the current query results and the lookup index.
- Multi-valued join field entries do not match anything; added fields contain `null` for those rows.
- Each field name in an expression join condition must exist in only one index. Use `RENAME` to resolve naming conflicts.
- Expression join conditions are in preview for the listed deployment types and versions.
