# EVAL

The `EVAL` processing command appends new columns with calculated values. `EVAL` supports functions for calculating values.

## Syntax

`EVAL [column1 =] value1[, ..., [columnN =] valueN]`

### Parameters

#### columnX

Optional. The column name. If a column with the same name already exists, the existing column is dropped. If a column name is used more than once, only the rightmost duplicate creates a column.

#### valueX

The value for the column. Can be a literal, an expression, or a function. Can use columns defined left of this one.

## Examples

Append calculated height conversion columns:

```esql
FROM employees
| SORT emp_no
| KEEP first_name, last_name, height
| EVAL height_feet = height * 3.281, height_cm = height * 100
```

Overwrite the existing `height` column with a calculated value:

```esql
FROM employees
| SORT emp_no
| KEEP first_name, last_name, height
| EVAL height = height * 3.281
```

Add an auto-named column using the expression as the column name:

```esql
FROM employees
| SORT emp_no
| KEEP first_name, last_name, height
| EVAL height * 3.281
```

Reference an auto-named column with backticks in a subsequent command:

```esql
FROM employees
| EVAL height * 3.281
| STATS avg_height_feet = AVG(`height * 3.281`)
```

## Limitations

Runtime fields defined in the index mapping are respected, but new runtime fields cannot be defined at search time. Use `EVAL` to create computed columns at query time instead.
