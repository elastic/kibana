# SORT

The `SORT` processing command sorts a table on one or more expressions. The default sort order is ascending. Use `ASC` or `DESC` to specify an explicit sort order.

## Syntax

`SORT expression1 [ASC/DESC][NULLS FIRST/NULLS LAST][, ..., expressionN [ASC/DESC][NULLS FIRST/NULLS LAST]]`

### Parameters

#### `expressionX`

The expression to sort on. Can be a column name, a function such as `length(field)` or `DATE_EXTRACT("year", date)`, or an arithmetic expression such as `salary * 2`. The expression is evaluated per row and the result is used for ordering.

Two rows with the same sort key are considered equal. You can provide additional sort expressions to act as tie breakers.

Sorting on multivalued columns uses the lowest value when sorting ascending and the highest value when sorting descending.

By default, `null` values are treated as being larger than any other value. With an ascending sort order, `null` values are sorted last, and with a descending sort order, `null` values are sorted first. You can change that by providing `NULLS FIRST` or `NULLS LAST`.

## Examples

Sort employee heights in default ascending order.

```esql
FROM employees
| KEEP first_name, last_name, height
| SORT height
```

Sort employee heights in descending order with `DESC`.

```esql
FROM employees
| KEEP first_name, last_name, height
| SORT height DESC
```

Sort employee heights descending and use `first_name` ascending as a tie breaker.

```esql
FROM employees
| KEEP first_name, last_name, height
| SORT height DESC, first_name ASC
```

Sort employee first names ascending and place `null` values first.

```esql
FROM employees
| KEEP first_name, last_name, height
| SORT first_name ASC NULLS FIRST
```

Sort rows by the length of the `first_name` field in descending order.

```esql
FROM employees
| KEEP first_name, last_name
| SORT length(first_name) DESC
| LIMIT 5
```
