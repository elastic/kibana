# FORK

The `FORK` processing command creates multiple execution branches that operate on the same input data and combines the results in a single output table. It adds a `_fork` discriminator column to identify which branch each row came from.

`FORK` merges branch outputs into one table. The `_fork` column uses values like `fork1`, `fork2`, and `fork3`, matching the order of the branches. Branches can output different columns, but columns with the same name must have the same data type across all branches. Missing columns are filled with `null` values. Row order is preserved within each branch, but rows from different branches may be interleaved. Use `SORT _fork` to group results by branch.

Together with the `FUSE` command, `FORK` enables hybrid search to combine and score results from multiple queries.

## Syntax

`FORK ( <processing_commands> ) ( <processing_commands> ) ... ( <processing_commands> )`

### Parameters

#### <processing_commands>

The processing commands to run in an execution branch. Each parenthesized group defines one branch that receives the same input data.

## Examples

Run two branches that each filter for a specific employee number, then show which branch returned each matching row:

```esql
FROM employees
| FORK ( WHERE emp_no == 10001 )
       ( WHERE emp_no == 10002 )
| KEEP emp_no, _fork
| SORT emp_no
```

| emp_no:integer | _fork:keyword |
| --- | --- |
| 10001 | fork1 |
| 10002 | fork2 |

Return the top matching authors for a search term in one branch and the total number of matches in another branch:

```esql
FROM books METADATA _score
| WHERE author:"Faulkner"
| EVAL score = round(_score, 2)
| FORK (SORT score DESC, author | LIMIT 5 | KEEP author, score)
       (STATS total = COUNT(*))
| SORT _fork, score DESC, author
```

| author:text | score:double | _fork:keyword | total:long |
| --- | --- | --- | --- |
| Colleen Faulkner | 2.18 | fork1 | null |
| William Faulkner | 2.18 | fork1 | null |
| Danny Faulkner | 2.02 | fork1 | null |
| Paul Faulkner | 2.02 | fork1 | null |
| William Faulkner | 2.02 | fork1 | null |
| null | null | fork2 | 18 |

## Limitations

- In Elastic Cloud Serverless and Elastic Stack 9.6 and later, `FORK` supports at most 8 execution branches by default. The limit is controlled by the `esql.query.max_branch_count_per_merge` cluster setting.
- In Elastic Stack 9.1 to 9.5, `FORK` supports at most 8 execution branches.
- In Elastic Stack 9.1 to 9.3, an implicit `LIMIT 1000` is added to each `FORK` branch.
- In versions older than 9.3.0, using remote cluster references and `FORK` is not supported.
- Using more than one `FORK` command in a query is not supported.
