# GROK

`GROK` enables you to extract structured data from a string. It matches the string against regular expression-based patterns and extracts the specified patterns as columns.

## Syntax

`GROK input "pattern"`

### Parameters

#### input

The column that contains the string you want to structure. If the column has multiple values, `GROK` will process each value.

#### pattern

A grok pattern. If a field name conflicts with an existing column, the existing column is discarded. If a field name is used more than once, a multi-valued column will be created with one value per occurrence of the field name.

## Examples

Parse a structured timestamp, IP address, email address, and number into separate columns:

```esql
ROW a = "2023-01-23T12:15:00.000Z 127.0.0.1 some.email@foo.com 42"
| GROK a """%{TIMESTAMP_ISO8601:date} %{IP:ip} %{EMAILADDRESS:email} %{NUMBER:num}"""
| KEEP date, ip, email, num
```

| date:keyword | ip:keyword | email:keyword | num:keyword |
|---|---|---|---|
| 2023-01-23T12:15:00.000Z | 127.0.0.1 | some.email@foo.com | 42 |

Convert a numeric capture to an integer with the `:type` suffix:

```esql
ROW a = "2023-01-23T12:15:00.000Z 127.0.0.1 some.email@foo.com 42"
| GROK a """%{TIMESTAMP_ISO8601:date} %{IP:ip} %{EMAILADDRESS:email} %{NUMBER:num:int}"""
| KEEP date, ip, email, num
```

| date:keyword | ip:keyword | email:keyword | num:integer |
|---|---|---|---|
| 2023-01-23T12:15:00.000Z | 127.0.0.1 | some.email@foo.com | 42 |

Convert a captured timestamp to a date with a type conversion function:

```esql
ROW a = "2023-01-23T12:15:00.000Z 127.0.0.1 some.email@foo.com 42"
| GROK a """%{TIMESTAMP_ISO8601:date} %{IP:ip} %{EMAILADDRESS:email} %{NUMBER:num:int}"""
| KEEP date, ip, email, num
| EVAL date = TO_DATETIME(date)
```

| ip:keyword | email:keyword | num:integer | date:date |
|---|---|---|---|
| 127.0.0.1 | some.email@foo.com | 42 | 2023-01-23T12:15:00.000Z |

Create a multi-valued column from duplicate grok field names:

```esql
FROM addresses
| KEEP city.name, zip_code
| GROK zip_code """%{WORD:zip_parts} %{WORD:zip_parts}"""
```

| city.name:keyword | zip_code:keyword | zip_parts:keyword |
|---|---|---|
| Amsterdam | 1016 ED | ["1016", "ED"] |
| San Francisco | CA 94108 | ["CA", "94108"] |
| Tokyo | 100-7014 | null |

## Limitations

The `:type` suffix supports `int` and `float` conversions. For other type conversions, use type conversion functions.

If a typed capture matches a value that cannot be converted, such as `%{NUMBER:num:int}` matching `1.5`, the row is treated as a failed match: all extracted columns are `null` for that row, and a warning is added to the response.
