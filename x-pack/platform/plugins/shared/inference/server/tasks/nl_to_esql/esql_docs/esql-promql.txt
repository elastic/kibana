# PROMQL

The `PROMQL` source command queries time series indices using **Prometheus Query Language (PromQL)**. Like `TS`, it enables time series aggregation functions, but accepts PromQL syntax.

`PROMQL` supports most, but not all, of PromQL. Refer to Prometheus compatibility for unsupported constructs and differences from Prometheus, and to PromQL functions for the supported functions and their restrictions.

## Syntax

The `PROMQL` command accepts zero or more space-separated `<option>=<value>` pairs, followed by a PromQL expression in parentheses that can be prefixed with a result name.

`PROMQL [ <option>=<value> ... ]  <result_name>=`

### Parameters

#### `index`

Optional.

A list of indices, data streams, or aliases. Supports wildcards and date math. Defaults to `metrics-*`, querying matching indices with `index.mode: time_series`.

Example: `PROMQL index=metrics-*.otel-* http_rate=(sum(rate(http_requests_total)))`

#### `step`

Optional.

Query resolution step width. Automatically determined given the number of target `buckets` and the selected time range.

Example: `PROMQL step=1m http_rate=(sum(rate(http_requests_total)))`

#### `buckets`

Optional.

Target number of buckets for auto-step derivation. Defaults to `100`. Mutually exclusive with `step`. Requires a known time range, either by setting `start` and `end` explicitly or implicitly through Kibana's time range filter.

Example: `PROMQL buckets=50 start="2026-04-01T00:00:00Z" end="2026-04-01T01:00:00Z" http_rate=(sum(rate(http_requests_total)))`

#### `start`

Optional.

Start time of the query, inclusive. Uses the start based on Kibana's date picker if missing. Set together with `end`.

Example: `PROMQL start="2026-04-01T00:00:00Z" end="2026-04-01T01:00:00Z" http_rate=(sum(rate(http_requests_total)))`

#### `end`

Optional.

End time of the query, inclusive. Uses the end based on Kibana's date picker if missing. Set together with `start`, and not before it.

Example: `PROMQL start="2026-04-01T00:00:00Z" end="2026-04-01T02:00:00Z" http_rate=(sum(rate(http_requests_total)))`

#### `time`

Optional.

Applies to: Elastic Stack: Generally available since 9.5. Applies to: Elastic Cloud Serverless: Generally available.

Evaluation time of an instant query. Evaluates the expression once, at this time, instead of at each step of a range query. Mutually exclusive with `start`, `end`, `step`, and `buckets`.

Example: `PROMQL time="2026-04-01T01:00:00Z" http_rate=(sum(rate(http_requests_total)))`

#### `scrape_interval`

Optional.

The expected metric collection interval. Defaults to `1m`. Used to determine implicit range selector windows as `max(step, scrape_interval)`.

Example: `PROMQL scrape_interval=15s http_rate=(sum(rate(http_requests_total)))`

#### `<result_name>=(<PromQL Expression>)`

Optional.

Name of the output column with the query result timeseries. By default, the name of the output column is the PromQL expression itself.

Example: `PROMQL http_rate=(sum by (instance) (rate(http_requests_total))) | SORT http_rate DESC`

`start`, `end`, and `time` accept an RFC 3339 timestamp with a UTC offset, such as `"2026-04-01T00:00:00Z"`, or a Unix timestamp in seconds, which can be fractional, such as `1775001600`. Date math, such as `now-1h`, isn't supported. In Kibana, the `?_tstart` and `?_tend` parameters reference the time range of the date picker, such as `time=?_tend`.

`step` and `scrape_interval` accept a PromQL duration, such as `30s` or `5m`, or a number of seconds.

## Examples

Run a fully adaptive query that uses Kibana's date picker, inferred step size, and inferred range selectors.

```esql
PROMQL index=metrics-generic.prometheus-* http_rate=(sum(rate(http_requests_total)))
```

Run an instant query that evaluates a metric expression once at a specific timestamp.

```esql
PROMQL index=metrics-generic.prometheus-*
  time="2026-04-01T01:00:00Z"
  http_rate=(sum(rate(http_requests_total)))
```

Aggregate network cost across series by `cluster` and sort the result.

```esql
PROMQL index=k8s step=1h result=(sum by (cluster) (network.cost))
| SORT result
```

result:double | step:datetime | cluster:keyword
--- | --- | ---
15.875 | 2024-05-10T00:00:00.000Z | staging
18.625 | 2024-05-10T00:00:00.000Z | prod
26.5 | 2024-05-10T00:00:00.000Z | qa

Filter labels in the PromQL selector, name the result `cost`, and sort by `cluster`.

```esql
PROMQL index=k8s step=1h cost=(max by (cluster) (network.total_bytes_in{cluster!="prod"}))
| SORT cluster
```

cost:double | step:datetime | cluster:keyword
--- | --- | ---
10797.0 | 2024-05-10T00:00:00.000Z | qa
7403.0 | 2024-05-10T00:00:00.000Z | staging

Pipe PromQL results into additional processing commands for aggregation by `cluster`.

```esql
PROMQL index=k8s step=1h bytes=(max by (cluster) (network.bytes_in))
| STATS max_bytes=MAX(bytes) BY cluster
| SORT cluster
```

max_bytes:double | cluster:keyword
--- | ---
931.0 | prod
972.0 | qa
238.0 | staging

Run an ad-hoc query with explicit `start` and `end` times and inferred step size.

```esql
PROMQL index=metrics-generic.prometheus-*
  start="2026-04-01T00:00:00Z"
  end="2026-04-01T01:00:00Z"
  http_rate=(sum(rate(http_requests_total)))
```

Join PromQL results grouped by `instance` with external instance metadata.

```esql
PROMQL index=metrics-generic.prometheus-*
  http_rate=(sum by (instance) (rate(http_requests_total)))
| LOOKUP JOIN instance_metadata ON instance
```

Get the current request rate at the end of Kibana's selected time range.

```esql
PROMQL index=metrics-generic.prometheus-* time=?_tend http_rate=(sum(rate(http_requests_total)))
```

Get the total number of requests over Kibana's selected time range.

```esql
PROMQL index=metrics-generic.prometheus-* time=?_tend
  total_requests=(sum(increase(http_requests_total[?_tend - ?_tstart])))
```

## Limitations

`PROMQL` supports most, but not all, PromQL constructs. The main limitations and behavior differences are:

- A range query needs either `step`, or both `start` and `end`, from which the step is derived using `buckets`. Without a time range and without `step`, the query fails.
- `start`, `end`, and `time` don't support date math such as `now-1h`.
- Native histograms can't be returned directly as the query result. Wrap native histograms in a histogram function, such as `histogram_count`.
- `rate` on native histograms isn't supported. Use `increase`, for example `histogram_quantile(0.99, sum by (job) (increase(h[5m])))`.
- Range vectors can't be returned as the result of an instant query.
- Selectors without a metric name, regex matchers on `__name__`, the `@` modifier, subqueries, and `anchored` or `smoothed` range selector modifiers aren't supported.
- Negative matchers on `__name__` return no results instead of matching every other metric.
- Negative offsets don't read samples after the query end, so they can return no value at the last steps.
- Lookback and staleness behavior differs from Prometheus: instant queries use a fixed five-minute lookback, range queries use one `step`, and staleness markers are ignored.
- Arithmetic with native histogram operands isn't supported.
- The trigonometric binary operator `atan2` isn't supported.
- Comparison operators have restrictions: filters with a scalar as the first operand, non-literal scalar second operands, two-vector comparisons, and comparisons inside another expression aren't supported.
- Logical/set operators are limited. `or` between instant vectors is supported, but `and`, `unless`, `or` with `on(...)` or `ignoring(...)`, and `or` inside another expression aren't supported. An `or` chain takes at most 8 operands by default.
- Vector matching is limited for unaggregated metrics, differently aggregated operands, nested aggregations, different `offset` values per operand, and `label_replace` or `label_join` as an operand.
- The `group` aggregation operator isn't supported.
- Some aggregation forms are restricted, including `topk`, `bottomk`, `limitk`, `limit_ratio`, and `count_values` with `without(...)`, nested `without(...)`, and `without(...)` as an operand.
- Grouping by a label named `step`, or using `count_values` with a label named `step`, `_timeseries`, or the same name as the value column, isn't supported because those names are output columns.
- Some functions aren't supported yet, including `absent`, `resets`, `info`, `histogram_stddev`, `histogram_stdvar`, `step()`, `range()`, `start()`, and `end()`.
- Some function parameters must be number literals, such as parameters to `clamp_min`, `histogram_quantile`, `topk`, and `quantile`.
- `label_replace` and `label_join` have restrictions on where they can be used and which labels they can write.
- `quantile` and `quantile_over_time` are approximate, using t-digest.
- `rate` and `increase` are computed over fixed time buckets and interpolated at bucket boundaries, so results can differ slightly from Prometheus.
