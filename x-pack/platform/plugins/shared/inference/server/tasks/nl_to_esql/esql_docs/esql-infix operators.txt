# INFIX OPERATORS

Infix operators provide shorthand syntax for type casting, list membership tests, wildcard pattern matching, regular expression matching, and full-text search.

## Syntax

- Cast `::`
- `IN`
- `LIKE`
- `RLIKE`
- Match `:`

### Parameters

#### `::`

The cast operator provides a convenient alternative syntax to the `TO_<type>` conversion functions.

#### `IN`

The `IN` operator tests whether a field or expression equals an element in a list of literals, fields, or expressions. You can also use a subquery with `IN` or `NOT IN` to compare a field or a tuple of fields against the results of another query, in `WHERE`, `EVAL`, and the per-aggregate `WHERE` of `STATS` and `INLINE STATS`.

#### `LIKE`

The `LIKE` operator filters data based on string patterns using wildcards. `LIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

The following wildcard characters are supported:

- `*` matches zero or more characters.
- `?` matches one character.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match. Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_LOWER`.

#### `RLIKE`

The `RLIKE` operator filters data based on string patterns using regular expressions. `RLIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match. Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_UPPER`.

#### `:`

The match operator performs full-text search and filters rows that match a given query string. It performs a match query on the specified field or expression and returns true if the provided query matches the row.

The match operator is equivalent to the match function. It can also search expressions that are not backed by an index, such as computed columns produced by `EVAL` or `STATS`.

## Examples

Cast integers and strings into a version value.

```esql
ROW ver = CONCAT(("0"::INT + 1)::STRING, ".2.3")::VERSION
```

Test whether an arithmetic expression equals one value in a literal and expression list.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

Filter employees whose first name matches a wildcard pattern.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal `*` character with `LIKE`.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character with `LIKE` and triple-quoted strings.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows path prefix with `LIKE`.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Match a message against a list of `LIKE` patterns.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Use a REST query placeholder as a `LIKE` pattern.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as a `LIKE` pattern.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose first name matches a regular expression.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal `(` character with `RLIKE`.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character with `RLIKE` and triple-quoted strings.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Match a message against a list of regular expression patterns.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Use a REST query placeholder as an `RLIKE` pattern.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as an `RLIKE` pattern.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Perform full-text search on a `text` field with the match operator.

```esql
FROM books
| WHERE author:"Faulkner"
```

Filter multi-valued keyword columns with the match operator.

```esql
FROM employees
| WHERE job_positions:"Internship"
| KEEP emp_no, job_positions
```

Run semantic search on a `semantic_text` field and sort by relevance score.

```esql
FROM books METADATA _score
| WHERE semantic_title:"Shakespeare"
| SORT _score DESC
| KEEP _score, semantic_title
```

## Limitations

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact indexed string. To perform full-text search, use the `MATCH` or `QSTR` functions.

For `LIKE`, matching the exact characters `*` and `?` requires escaping with backslash `\`. Because backslash is also special in string literals, it requires further escaping.

For `RLIKE`, matching special characters such as `.`, `*`, and `(` requires escaping with backslash `\`. Because backslash is also special in string literals, it requires further escaping.

When the match operator targets an expression that is not backed by an index, the search evaluates by scanning values row by row, which may be slower on large datasets.
