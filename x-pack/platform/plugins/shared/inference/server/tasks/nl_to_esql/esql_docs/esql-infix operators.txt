# INFIX OPERATORS

Infix operators provide expression syntax for casting values, testing membership, matching wildcard or regular-expression patterns, and performing full-text search.

## Syntax

- Cast: `expression::type`
- `expression IN (value[, ...])`
- `expression LIKE pattern`
- `expression RLIKE pattern`
- Match: `field:query`

### Parameters

#### `::`

The cast operator provides a convenient alternative syntax to the `TO_<type>` conversion functions.

#### `IN`

The `IN` operator tests whether a field or expression equals an element in a list of literals, fields, or expressions. You can also use a subquery with `IN` or `NOT IN` to compare a field or a tuple of fields against the results of another query in `WHERE`, `EVAL`, and the per-aggregate `WHERE` of `STATS` and `INLINE STATS`.

#### `LIKE`

The `LIKE` operator filters data based on string patterns using wildcards. `LIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

The following wildcard characters are supported:

- `*` matches zero or more characters.
- `?` matches one character.

Both a single pattern and a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match. Patterns may also be specified with REST query placeholders or constant expressions.

#### `RLIKE`

The `RLIKE` operator filters data based on string patterns using regular expressions. `RLIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

Both a single pattern and a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match. Patterns may also be specified with REST query placeholders or constant expressions.

#### `:`

The match operator performs full-text search and filters rows that match a given query string. It performs a match query on the specified field or expression and returns true if the provided query matches the row.

The match operator can also search expressions that are not backed by an index, such as computed columns produced by `EVAL` or `STATS`.

## Examples

Cast integer and string values into a version value.

```esql
ROW ver = CONCAT(("0"::INT + 1)::STRING, ".2.3")::VERSION
```

Test whether an arithmetic expression matches one value in a mixed list.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

Filter employees whose first name matches a wildcard pattern.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal `*` character with an escaped wildcard.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character using a triple-quoted string.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows-style path with a triple-quoted string.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Filter rows by matching any wildcard pattern in a pattern list.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Filter employees with a wildcard pattern supplied through a REST query placeholder.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Filter employees using a constant expression as the wildcard pattern.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose first name matches a regular expression.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal `(` character with an escaped regular-expression character.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character using a triple-quoted string.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Filter rows by matching any regular expression in a pattern list.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Filter employees with a regular-expression pattern supplied through a REST query placeholder.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Filter employees using a constant expression as the regular-expression pattern.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Search a text field for rows whose author matches `Faulkner`.

```esql
FROM books
| WHERE author:"Faulkner"
```

Filter multi-valued keyword columns for the `Internship` job position.

```esql
FROM employees
| WHERE job_positions:"Internship"
| KEEP emp_no, job_positions
```

Run semantic search on `semantic_text` fields and sort by relevance score.

```esql
FROM books METADATA _score
| WHERE semantic_title:"Shakespeare"
| SORT _score DESC
| KEEP _score, semantic_title
```

## Limitations

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact indexed string. To perform full-text search, use the `MATCH` or `QSTR` functions.

Matching literal wildcard or regular-expression characters with `LIKE` and `RLIKE` requires escaping. Backslash is also special in string literals, so it may require additional escaping. Triple-quoted strings can reduce escaping overhead.

When the match operator searches an expression that is not backed by an index, the search scans values row by row, which may be slower on large datasets.
