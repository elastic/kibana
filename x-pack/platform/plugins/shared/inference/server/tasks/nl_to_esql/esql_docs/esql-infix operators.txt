# INFIX OPERATORS

Infix operators cast values, test membership, match wildcard or regular-expression patterns, and perform full-text matching.

## Syntax

- Cast `::`
- `IN`
- `LIKE`
- `RLIKE`
- Match `:`

`INFIX OPERATORS()`

### Parameters

#### Cast (`::`)

The `::` operator provides a convenient alternative syntax to the `TO_<type>` conversion functions.

#### `IN`

The `IN` operator tests whether a field or expression equals an element in a list of literals, fields, or expressions.

You can also use a subquery with `IN` or `NOT IN` to compare a field or a tuple of fields against the results of another query, in `WHERE`, `EVAL`, and the per-aggregate `WHERE` of `STATS` and `INLINE STATS`.

#### `LIKE`

The `LIKE` operator filters data based on string patterns using wildcards. `LIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

The following wildcard characters are supported:

- `*` matches zero or more characters.
- `?` matches one character.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match.

Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_LOWER`.

#### `RLIKE`

The `RLIKE` operator filters data based on string patterns using regular expressions. `RLIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match.

Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_UPPER`.

#### Match operator (`:`)

The match operator (`:`) performs full-text search and filters rows that match a given query string.

The match operator performs a match query on the specified field or expression. It returns true if the provided query matches the row. The match operator is equivalent to the match function, which is the standard function for performing full-text search.

The match operator can also search expressions that are not backed by an index, such as computed columns produced by `EVAL` or `STATS`.

## Examples

Cast values across integer, string, and version types to build a version value:

```esql
ROW ver = CONCAT(("0"::INT + 1)::STRING, ".2.3")::VERSION
```

Test whether an expression matches any value in an `IN` list:

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

Filter employee names with a wildcard pattern:

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal `*` character with escaping:

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character with triple-quoted strings:

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows-style path with triple-quoted strings:

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Match a string against any wildcard pattern in a pattern list:

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Use a REST query placeholder as a `LIKE` pattern:

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as a `LIKE` pattern:

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employee names with a regular expression:

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal `(` character with escaping:

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character with triple-quoted strings:

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Match a string against any regular expression in a pattern list:

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Use a REST query placeholder as an `RLIKE` pattern:

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as an `RLIKE` pattern:

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Search a `text` field with the match operator:

```esql
FROM books
| WHERE author:"Faulkner"
```

Filter multi-valued `keyword` columns with the match operator:

```esql
FROM employees
| WHERE job_positions:"Internship"
| KEEP emp_no, job_positions
```

Run semantic search and sort by relevance score:

```esql
FROM books METADATA _score
| WHERE semantic_title:"Shakespeare"
| SORT _score DESC
| KEEP _score, semantic_title
```

## Limitations

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact string indexed. To perform full-text search, use the `MATCH` or `QSTR` functions.

Matching the exact characters `*` and `?` with `LIKE` requires escaping. Matching special characters, such as `.`, `*`, or `(`, with `RLIKE` also requires escaping.

When the match operator searches expressions that are not backed by an index, the search scans values row by row, which may be slower on large datasets.
