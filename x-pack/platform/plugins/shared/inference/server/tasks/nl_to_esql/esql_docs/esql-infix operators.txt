# INFIX OPERATORS

Infix operators provide shorthand syntax for casting values, testing membership, matching wildcard or regular-expression patterns, and running full-text match queries.

## Syntax

- Cast `::`
- `IN`
- `LIKE`
- `RLIKE`
- Match `:`

### Parameters

#### Cast (`::`)

The `::` operator provides a convenient alternative syntax to the `TO_<type>` conversion functions.

#### IN

The `IN` operator allows testing whether a field or expression equals an element in a list of literals, fields, or expressions.

You can also use a subquery with `IN` or `NOT IN` to compare a field or a tuple of fields against the results of another query, in `WHERE`, `EVAL`, and the per-aggregate `WHERE` of `STATS` and `INLINE STATS`.

#### LIKE

Use `LIKE` to filter data based on string patterns using wildcards. `LIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

The following wildcard characters are supported:

- `*` matches zero or more characters.
- `?` matches one character.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match.

Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_LOWER`.

#### RLIKE

Use `RLIKE` to filter data based on string patterns using regular expressions. `RLIKE` usually acts on a field placed on the left-hand side of the operator, but it can also act on a constant expression. The right-hand side of the operator represents the pattern.

Both a single pattern or a list of patterns are supported. If a list of patterns is provided, the expression returns true if any of the patterns match.

Patterns may be specified with REST query placeholders. The pattern can also be any constant expression, such as a call to `CONCAT` or `TO_UPPER`.

#### Match operator (`:`)

Use the match operator (`:`) to perform full-text search and filter rows that match a given query string.

The match operator performs a match query on the specified field or expression. It returns true if the provided query matches the row.

The match operator can also search expressions that are not backed by an index, such as computed columns produced by `EVAL` or `STATS`.

## Examples

Create a `version` value by casting numeric and string expressions.

```esql
ROW ver = CONCAT(("0"::INT + 1)::STRING, ".2.3")::VERSION
```

Filter a row by testing an arithmetic expression against literals and expressions.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

Filter employees whose first name matches a wildcard pattern.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

Match a literal asterisk in a string with escaped wildcards.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal asterisk with a triple-quoted string pattern.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows path prefix with triple-quoted strings.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Match a message against a list of wildcard patterns.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Filter employee names with a wildcard pattern supplied by a REST query placeholder.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Build a wildcard pattern with `CONCAT` and filter employee names.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose first name matches a regular expression.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

Match a literal opening parenthesis in a string with escaped regular-expression syntax.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal opening parenthesis with a triple-quoted regular-expression pattern.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Match a message against a list of regular-expression patterns.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Filter employee names with a regular-expression pattern supplied by a REST query placeholder.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Build a regular-expression pattern with `CONCAT` and filter employee names.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Perform full-text search on a `text` field.

```esql
FROM books
| WHERE author:"Faulkner"
```

Filter multi-valued `keyword` columns with the match operator.

```esql
FROM employees
| WHERE job_positions:"Internship"
| KEEP emp_no, job_positions
```

Run semantic search on `semantic_text` fields and sort by relevance score.

```esql
FROM books METADATA _score
| WHERE semantic_title:"Shakespeare"
| SORT _score DESC
| KEEP _score, semantic_title
```

## Limitations

When used on `text` fields, `LIKE` and `RLIKE` treat the field as a `keyword` and do not use the analyzer. Pattern matching is case-sensitive and must match the exact indexed string. To perform full-text search, use the `MATCH` or `QSTR` functions.

Matching exact wildcard characters with `LIKE`, such as `*` and `?`, requires escaping. Matching special characters with `RLIKE`, such as `.`, `*`, or `(`, also requires escaping.

When the match operator searches a target that is not an indexed field, the search evaluates by scanning values row by row, which may be slower on large datasets.
