# INFIX OPERATORS

Infix operators compare, match, cast, and filter values using operators placed between expressions. Supported operators include cast `::`, `IN`, `LIKE`, `RLIKE`, and match `:`.

## Syntax

- `expression::TYPE`
- `expression IN (value[, ...])`
- `expression LIKE pattern`
- `expression RLIKE pattern`
- `field:query`

### Parameters

#### expression

An expression, field, or literal value used on the left-hand side of an infix operator.

#### TYPE

The target type for the cast operator `::`. The cast operator provides a convenient alternative syntax to the `TO_<type>` conversion functions.

#### value

A literal, field, or expression used in an `IN` list. The `IN` operator tests whether a field or expression equals an element in the list.

#### pattern

A string pattern used by `LIKE` or `RLIKE`. `LIKE` supports wildcard patterns, while `RLIKE` supports regular expressions.

For `LIKE`, the wildcard character `*` matches zero or more characters, and `?` matches one character.

#### field

The field or expression searched by the match operator `:`.

#### query

The query string used by the match operator `:`. The match operator performs a match query on the specified field or expression and returns `true` if the query matches the row.

## Examples

Cast integer and string values into a version value.

```esql
ROW ver = CONCAT(("0"::INT + 1)::STRING, ".2.3")::VERSION
```

ver:version  
1.2.3

Test whether an expression matches any value in an `IN` list.

```esql
ROW a = 1, b = 4, c = 3
| WHERE c-a IN (3, b / 2, a)
```

a:integer | b:integer | c:integer  
1 | 4 | 3

Filter employees whose first name matches a `LIKE` wildcard pattern.

```esql
FROM employees
| WHERE first_name LIKE """?b*"""
| KEEP first_name, last_name
```

first_name:keyword | last_name:keyword  
Ebbe | Callaway  
Eberhardt | Terkki

Match a literal `*` character in a `LIKE` pattern.

```esql
ROW message = "foo * bar"
| WHERE message LIKE "foo \\* bar"
```

Match a literal `*` character with a triple-quoted `LIKE` pattern.

```esql
ROW message = "foo * bar"
| WHERE message LIKE """foo \* bar"""
```

Match a Windows-style path with a triple-quoted `LIKE` pattern.

```esql
ROW path = """C:\Windows\System32\foo.txt"""
| WHERE path LIKE """C:\\Windows*"""
```

Match a string against any pattern in a `LIKE` pattern list.

```esql
ROW message = "foobar"
| WHERE message like ("foo*", "bar?")
```

Use a REST query placeholder as a `LIKE` pattern.

```esql
FROM employees
| WHERE first_name LIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as a `LIKE` pattern.

```esql
from employees | where first_name like concat("Eber", "*") | keep emp_no, first_name
```

Filter employees whose first name matches an `RLIKE` regular expression.

```esql
FROM employees
| WHERE first_name RLIKE """.leja.*"""
| KEEP first_name, last_name
```

first_name:keyword | last_name:keyword  
Alejandro | McAlpine

Match a literal `(` character in an `RLIKE` pattern.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE "foo \\( bar"
```

Match a literal `(` character with a triple-quoted `RLIKE` pattern.

```esql
ROW message = "foo ( bar"
| WHERE message RLIKE """foo \( bar"""
```

Match a string against any pattern in an `RLIKE` pattern list.

```esql
ROW message = "foobar"
| WHERE message RLIKE ("foo.*", "bar.")
```

Use a REST query placeholder as an `RLIKE` pattern.

```esql
FROM employees
| WHERE first_name RLIKE ?pattern
| KEEP first_name, last_name
```

Use a constant expression as an `RLIKE` pattern.

```esql
from employees | where first_name rlike concat("Eber", ".*") | keep emp_no, first_name
```

Perform full-text search on a `text` field with the match operator.

```esql
FROM books
| WHERE author:"Faulkner"
```

book_no:keyword | author:text  
2378 | [Carol Faulkner, Holly Byers Ochoa, Lucretia Mott]  
2713 | William Faulkner  
2847 | Colleen Faulkner  
2883 | William Faulkner  
3293 | Danny Faulkner

Filter multi-valued `keyword` columns with the match operator.

```esql
FROM employees
| WHERE job_positions:"Internship"
| KEEP emp_no, job_positions
```

emp_no:integer | job_positions:keyword  
10008 | [Internship, Junior Developer, Purchase Manager, Senior Python Developer]  
10009 | [Internship, Senior Python Developer]  
10022 | [Data Scientist, Internship, Python Developer, Reporting Analyst]

Run semantic search with the match operator and sort by `_score`.

```esql
FROM books METADATA _score
| WHERE semantic_title:"Shakespeare"
| SORT _score DESC
| KEEP _score, semantic_title
```

_score:double | semantic_text_field:text  
9.5770 | Romeo and Juliet  
9.6850 | Hamlet  
8.232 | Othello

## Limitations

When `LIKE` or `RLIKE` is used on `text` fields, the field is treated as a `keyword` and the analyzer is not used. Pattern matching is case-sensitive and must match the exact indexed string. Use `MATCH` or `QSTR` for full-text search.

When the match operator searches expressions that are not backed by an index, such as computed columns produced by `EVAL` or `STATS`, values are scanned row by row and queries may be slower on large datasets.
