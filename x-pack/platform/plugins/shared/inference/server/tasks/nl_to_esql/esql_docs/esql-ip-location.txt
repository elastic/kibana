# IP-LOCATION

The `IP_LOCATION` processing command enriches rows with geographic information based on an IP address, using a MaxMind or IPinfo database.

The first `IP_LOCATION` query triggers a one-time download of IP location databases to all nodes in the cluster. These databases are periodically updated while the cluster is running.

The command resolves geographic information for an IP address and adds the results as new columns prefixed with the specified `prefix` followed by a dot (`.`). This command is the query-time equivalent of the GeoIP ingest processor.

## Syntax

`IP_LOCATION prefix = expression [WITH { option = value [, ...] }]`

### Parameters

#### `prefix`

The prefix for the output columns. The resolved fields are available as `prefix.field_name`.

For the default GeoLite2-City database, the default output columns are `prefix.country_iso_code`, `prefix.country_name`, `prefix.continent_name`, `prefix.region_iso_code`, `prefix.region_name`, `prefix.city_name`, and `prefix.location`.

#### `expression`

An expression that evaluates to an IP address of type `ip`, or a string containing an IP address.

#### `database_file`

Optional.

The name of the IP location database to use. Default: `GeoLite2-City.mmdb`. Supported databases include GeoLite2 and GeoIP2 variants, such as City, Country, and ASN databases, as well as IPinfo databases. To use a custom database, register it with the Create or update IP geolocation database configuration API first.

#### `properties`

Optional.

List of database property names to include in the output. Each value maps to one output column. Default: the database's default property set. For `GeoLite2-City`, the default property set is `country_iso_code`, `country_name`, `continent_name`, `region_iso_code`, `region_name`, `city_name`, and `location`.

Pass a subset to reduce the output schema. The list must contain at least one property; an empty list is not supported.

#### `first_only`

Optional.

Controls multi-value input handling. When `true`, the first IP value is used and the rest are ignored. When `false`, multi-value input is rejected with a warning and the row produces `null` for all output columns. Default: `true`.

## Examples

Resolve geographic information for an IPv6 address:

```esql
ROW ip = "2602:306:33d3:8000::3257:9652"
| IP_LOCATION g = ip
| KEEP g.country_iso_code, g.country_name, g.continent_name, g.region_iso_code, g.region_name, g.city_name
```

| g.country_iso_code:keyword | g.country_name:keyword | g.continent_name:keyword | g.region_iso_code:keyword | g.region_name:keyword | g.city_name:keyword |
|---|---|---|---|---|---|
| US | United States | North America | US-FL | Florida | Homestead |

Resolve only selected location properties for an IPv6 address:

```esql
ROW ip = "2602:306:33d3:8000::3257:9652"
| IP_LOCATION g = ip WITH { "properties": ["country_iso_code", "country_name", "continent_name", "region_iso_code", "region_name", "city_name"] }
```

Use the GeoLite2-Country database for an IPv4 address:

```esql
ROW ip = "82.170.213.79"
| IP_LOCATION g = ip WITH { "database_file": "GeoLite2-Country.mmdb" }
| KEEP g.*
```

Filter web logs by resolved country and count requests by city:

```esql
FROM web_logs
| IP_LOCATION geo = client_ip
| WHERE geo.country_iso_code == "US"
| STATS count = COUNT(*) BY geo.city_name
```

## Limitations

If the IP address is not found in the database, all output columns are `null`.

If the database is not yet available on the node, for example because it is still downloading, keyword output columns contain the sentinel value `_ip_location_database_unavailable_<database_file>` and non-keyword columns are `null`. A warning header indicates the unavailable database.

If the database has expired, keyword columns contain `_ip_location_expired_database` and non-keyword columns are `null`.

The `properties` list must contain at least one property; an empty list is not supported.

When `first_only` is `false`, multi-value input is rejected with a warning and the row produces `null` for all output columns.
