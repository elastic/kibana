# STATS-BY

The `STATS` processing command groups rows according to a common value and calculates one or more aggregated values over the grouped rows.

For each aggregated value, rows in a group can be filtered with `WHERE`. If `BY` is omitted, the output table contains exactly one row with the aggregations applied over the entire dataset. Individual `null` values are skipped when computing aggregations.

For fast approximate results with confidence intervals, see Approximate `STATS` queries.

Supported aggregation functions include `ABSENT`, `AVG`, `COUNT`, `COUNT_DISTINCT`, `EARLIEST`, `FIRST`, `LAST`, `LATEST`, `MAX`, `MEDIAN`, `MEDIAN_ABSOLUTE_DEVIATION`, `MIN`, `PERCENTILE`, `PRESENT`, `SAMPLE`, `SPARKLINE`, `ST_CENTROID_AGG`, `ST_EXTENT_AGG`, `STD_DEV`, `SUM`, `TOP`, `VALUES`, `VARIANCE`, and `WEIGHTED_AVG`.

When `STATS` is used under the `TS` source command, time series aggregation functions are also supported, with different semantics when `BY` is omitted or combined with `WITHOUT`.

Supported grouping functions include `BUCKET`, `CATEGORIZE`, `TBUCKET`, and `WITHOUT`.

## Syntax

`STATS [column1 =] expression1 [WHERE boolean_expression1][, ..., [columnN =] expressionN [WHERE boolean_expressionN]] [BY grouping_expression1[, ..., grouping_expressionN]]`

### Parameters

#### `columnX`

Optional.

The name by which the aggregated value is returned. If omitted, the name is equal to the corresponding expression (`expressionX`). If multiple columns have the same name, all but the rightmost column with this name will be ignored.

#### `expressionX`

An expression that computes an aggregated value.

#### `grouping_expressionX`

Optional.

An expression that outputs the values to group by. If its name coincides with one of the computed columns, that column will be ignored.

#### `boolean_expressionX`

Optional.

The condition that must be met for a row to be included in the evaluation of `expressionX`. Has no effect on `grouping_expressionX` or other aggregation expressions. Consequently, the following are not equivalent:

Applies the condition only to the aggregation within `STATS`, without filtering rows before aggregation:

```esql
... | STATS ... WHERE <condition> ...
```

Filters rows before they reach `STATS`, affecting all subsequent aggregations and groups:

```esql
... | WHERE <condition> | STATS ...
```

## Examples

Group rows by `languages` and count employee numbers in each group:

```esql
FROM employees
| STATS count = COUNT(emp_no) BY languages
| SORT languages
```

count:long | languages:integer
15 | 1
19 | 2
17 | 3
18 | 4
21 | 5
10 | null

Aggregate the whole `employees` dataset without grouping:

```esql
FROM employees
| STATS avg_lang = AVG(languages)
```

avg_lang:double
3.1222222222222222

Calculate average and maximum language counts in a single pass:

```esql
FROM employees
| STATS avg_lang = AVG(languages), max_lang = MAX(languages)
```

avg_lang:double | max_lang:integer
3.1222222222222222 | 5

Calculate conditional average salaries by `gender` using per-aggregation `WHERE` clauses:

```esql
FROM employees
| STATS avg50s = AVG(salary)::LONG WHERE birth_date < "1960-01-01",
        avg60s = AVG(salary)::LONG WHERE birth_date >= "1960-01-01"
        BY gender
| SORT gender
```

avg50s:long | avg60s:long | gender:keyword
55462 | 46637 | F
48279 | 44879 | M

Mix filtered and unfiltered salary-count aggregations in one result row:

```esql
FROM employees
| EVAL Ks = salary / 1000
| STATS under_40K = COUNT(*) WHERE Ks < 40,
        inbetween = COUNT(*) WHERE 40 <= Ks AND Ks < 60,
        over_60K  = COUNT(*) WHERE 60 <= Ks,
        total     = COUNT(*)
```

under_40K:long | inbetween:long | over_60K:long | total:long
36 | 39 | 25 | 100

Filter an aggregation on the grouping key while keeping all groups in the output:

```esql
FROM employees
| STATS `count` = COUNT(*) WHERE languages < 3 BY languages
```

count:long | languages:integer
15 | 1
19 | 2
0 | 3
0 | 4
0 | 5
0 | null

Filter rows before grouping so non-matching groups are excluded from the output:

```esql
FROM employees
| WHERE languages < 3
| STATS `count` = COUNT(*) BY languages
```

count:long | languages:integer
15 | 1
19 | 2

Group by multiple expressions, including a derived hire year and `languages.long`:

```esql
FROM employees
| EVAL hired = DATE_FORMAT("yyyy", hire_date)
| STATS avg_salary = AVG(salary) BY hired, languages.long
| EVAL avg_salary = ROUND(avg_salary)
| SORT hired, languages.long
```

Group a multivalued `color` key so the input row belongs to every color group:

```esql
ROW price = 10, color = ["blue", "pink", "yellow"]
| STATS SUM(price) BY color
```

SUM(price):long | color:keyword
10 | blue
10 | pink
10 | yellow

Group by multiple multivalued keys so the input row belongs to every color and size combination:

```esql
ROW price = 10, color = ["blue", "pink", "yellow"], size = ["s", "m", "l"]
| STATS SUM(price) BY color, size
```

SUM(price):long | color:keyword | size:keyword
10 | blue | l
10 | blue | m
10 | blue | s
10 | pink | l
10 | pink | m
10 | pink | s
10 | yellow | l
10 | yellow | m
10 | yellow | s

Aggregate all multivalued `color` values while grouping by each color value:

```esql
ROW color = ["blue", "pink", "yellow"]
| STATS VALUES(color) BY color
```

VALUES(color):keyword | color:keyword
[blue, pink, yellow] | blue
[blue, pink, yellow] | pink
[blue, pink, yellow] | yellow

Expand `color` before grouping so each group receives only its own color value:

```esql
ROW color = ["blue", "pink", "yellow"]
| MV_EXPAND color
| STATS VALUES(color) BY color
```

VALUES(color):keyword | color:keyword
blue | blue
pink | pink
yellow | yellow

Calculate average salary change by combining `MV_AVG`, `AVG`, and `ROUND`:

```esql
FROM employees
| STATS avg_salary_change = ROUND(AVG(MV_AVG(salary_change)), 10)
```

avg_salary_change:double
1.3904535865

Group by the first letter of `last_name` using `LEFT` as a grouping expression:

```esql
FROM employees
| STATS my_count = COUNT() BY LEFT(last_name, 1)
| SORT `LEFT(last_name, 1)`
```

Return an unnamed average salary aggregation with the default column name `AVG(salary)`:

```esql
FROM employees
| STATS AVG(salary)
```

AVG(salary):double
48248.55

Quote the default aggregation column name with backticks in a later command:

```esql
FROM employees
| STATS AVG(salary)
| EVAL avg_salary_rounded = ROUND(`AVG(salary)`)
```

AVG(salary):double | avg_salary_rounded:double
48248.55 | 48249.0

## Limitations

`STATS` without any groups is much faster than adding a group.

Grouping on a single expression is currently much more optimized than grouping on many expressions. Grouping on a single `keyword` column can be significantly faster than grouping on two `keyword` columns. Combining multiple columns with a function such as `CONCAT` and grouping on the combined value is not expected to be faster.
