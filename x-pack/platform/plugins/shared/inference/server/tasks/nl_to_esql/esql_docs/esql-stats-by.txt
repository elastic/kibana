# STATS-BY

The `STATS` processing command groups rows according to a common value and calculates one or more aggregated values over the grouped rows. For each aggregated value, rows in a group can be filtered with `WHERE`. If `BY` is omitted, the output table contains exactly one row with aggregations applied over the entire dataset.

Individual `null` values are skipped when computing aggregations.

The following aggregation functions are supported: `ABSENT`, `AVG`, `COUNT`, `COUNT_DISTINCT`, `EARLIEST`, `FIRST`, `LAST`, `LATEST`, `MAX`, `MEDIAN`, `MEDIAN_ABSOLUTE_DEVIATION`, `MIN`, `PERCENTILE`, `PRESENT`, `SAMPLE`, `SPARKLINE`, `ST_CENTROID_AGG`, `ST_EXTENT_AGG`, `STD_DEV`, `SUM`, `TOP`, `VALUES`, `VARIANCE`, and `WEIGHTED_AVG`.

When `STATS` is used under the `TS` source command, time series aggregation functions are also supported.

The following grouping functions are supported: `BUCKET`, `CATEGORIZE`, `TBUCKET`, and `WITHOUT`.

## Syntax

`STATS [column1 =] expression1 [WHERE boolean_expression1][, ..., [columnN =] expressionN [WHERE boolean_expressionN]] [BY grouping_expression1[, ..., grouping_expressionN]]`

### Parameters

#### `columnX`

Optional. The name by which the aggregated value is returned. If omitted, the name is equal to the corresponding expression (`expressionX`). If multiple columns have the same name, all but the rightmost column with this name will be ignored.

#### `expressionX`

An expression that computes an aggregated value.

#### `grouping_expressionX`

Optional. An expression that outputs the values to group by. If its name coincides with one of the computed columns, that column will be ignored.

#### `boolean_expressionX`

Optional. The condition that must be met for a row to be included in the evaluation of `expressionX`. Has no effect on `grouping_expressionX` or other aggregation expressions. Consequently, the following are not equivalent:

Apply a condition only to the aggregation expression, without filtering rows before grouping.

```esql
... | STATS ... WHERE <condition> ...
```

Filter rows before running `STATS`, which affects both grouping and aggregation.

```esql
... | WHERE <condition> | STATS ...
```

## Examples

Group employees by `languages` and count `emp_no` values.

```esql
FROM employees
| STATS count = COUNT(emp_no) BY languages
| SORT languages
```

Aggregate all employee rows into a single average `languages` value.

```esql
FROM employees
| STATS avg_lang = AVG(languages)
```

Calculate average and maximum `languages` values in a single pass.

```esql
FROM employees
| STATS avg_lang = AVG(languages), max_lang = MAX(languages)
```

Calculate conditional average salaries by `gender` for employees born before and after 1960.

```esql
FROM employees
| STATS avg50s = AVG(salary)::LONG WHERE birth_date < "1960-01-01",
        avg60s = AVG(salary)::LONG WHERE birth_date >= "1960-01-01"
        BY gender
| SORT gender
```

Count salary bands and total employees from the same dataset.

```esql
FROM employees
| EVAL Ks = salary / 1000
| STATS under_40K = COUNT(*) WHERE Ks < 40,
        inbetween = COUNT(*) WHERE 40 <= Ks AND Ks < 60,
        over_60K  = COUNT(*) WHERE 60 <= Ks,
        total     = COUNT(*)
```

Filter an aggregation by the grouping key while preserving all groups.

```esql
FROM employees
| STATS `count` = COUNT(*) WHERE languages < 3 BY languages
```

Filter rows before grouping so non-matching groups are excluded.

```esql
FROM employees
| WHERE languages < 3
| STATS `count` = COUNT(*) BY languages
```

Group average salary by hire year and `languages.long`.

```esql
FROM employees
| EVAL hired = DATE_FORMAT("yyyy", hire_date)
| STATS avg_salary = AVG(salary) BY hired, languages.long
| EVAL avg_salary = ROUND(avg_salary)
| SORT hired, languages.long
```

Group a row with one multivalued grouping key into all color groups.

```esql
ROW price = 10, color = ["blue", "pink", "yellow"]
| STATS SUM(price) BY color
```

Group a row with two multivalued grouping keys into every color and size combination.

```esql
ROW price = 10, color = ["blue", "pink", "yellow"], size = ["s", "m", "l"]
| STATS SUM(price) BY color, size
```

Show that aggregation functions receive the entire row when grouping by a multivalued key.

```esql
ROW color = ["blue", "pink", "yellow"]
| STATS VALUES(color) BY color
```

Expand multivalued `color` values before grouping so each aggregation receives one color value.

```esql
ROW color = ["blue", "pink", "yellow"]
| MV_EXPAND color
| STATS VALUES(color) BY color
```

Calculate average salary change using `MV_AVG` inside `AVG`.

```esql
FROM employees
| STATS avg_salary_change = ROUND(AVG(MV_AVG(salary_change)), 10)
```

Group employees by the first character of `last_name`.

```esql
FROM employees
| STATS my_count = COUNT() BY LEFT(last_name, 1)
| SORT `LEFT(last_name, 1)`
```

Return an aggregation column using the default expression-based column name.

```esql
FROM employees
| STATS AVG(salary)
```

Reference an expression-based aggregation column name with backticks.

```esql
FROM employees
| STATS AVG(salary)
| EVAL avg_salary_rounded = ROUND(`AVG(salary)`)
```

## Limitations

`STATS` without any groups is much faster than adding a group.

Grouping on a single expression is currently much more optimized than grouping on many expressions. Grouping on a single `keyword` column can be significantly faster than grouping on two `keyword` columns. Combining multiple columns with a function such as `CONCAT` before grouping is not expected to improve performance.
