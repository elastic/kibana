# TS

The `TS` source command targets time series indices, enables time series semantics, and adds support for time series aggregation functions in the `STATS` command, such as `AVG_OVER_TIME()` and `RATE`.

These functions are evaluated per time series, then aggregated by group using a secondary aggregation function. If a query is missing an inner time series aggregation function, `TS` selects a default based on the field type: numeric fields use `LAST_OVER_TIME()`, while histogram fields are merged.

If there is no `STATS` command in the query, the output of the `TS` command gets sorted by `@timestamp` in descending order by default.

## Syntax

`TS index_pattern [METADATA fields]`

### Parameters

#### index_pattern

A list of indices, data streams or aliases. Supports wildcards and date math.

#### fields

Optional.

A comma-separated list of metadata fields to retrieve.

## Examples

Compare raw counter summing with per-time-series rate aggregation.

Sum raw request counter values by host without applying time series semantics.

```esql
FROM metrics | STATS SUM(request_count) BY host
```

Calculate request rates per time series and sum those rates by host.

```esql
TS metrics | STATS SUM(RATE(request_count)) BY host
```

Compare raw CPU averaging with per-time-series bucketed averaging.

Average raw CPU usage values by cluster without applying time series semantics.

```esql
FROM metrics | STATS AVG(cpu_usage) BY cluster
```

Average CPU usage per time series and aggregate the results by cluster and one-minute time bucket.

```esql
TS metrics
| STATS AVG(AVG_OVER_TIME(cpu_usage)) BY cluster, TBUCKET(1 minute)
```

Calculate garbage collection event count, average duration, and 99th-percentile duration for histogram metrics.

```esql
TS metrics-*
| WHERE TRANGE(1 hour)
| STATS count = COUNT(jvm.gc.duration),
        avg = AVG(jvm.gc.duration),
        p99 = PERCENTILE(jvm.gc.duration, 99)
  BY jvm.gc.action, TBUCKET(5 minutes)
```

Calculate the total rate of search requests per host and hour.

```esql
TS metrics
  | WHERE @timestamp >= now() - 1 hour
  | STATS SUM(RATE(search_requests)) BY TBUCKET(1 hour), host
```

Aggregate memory usage with implicit `LAST_OVER_TIME`.

```esql
TS metrics | STATS AVG(memory_usage)

TS metrics | STATS AVG(LAST_OVER_TIME(memory_usage))
```

Calculate the average memory usage across per-time-series averages.

```esql
TS metrics | STATS AVG(AVG_OVER_TIME(memory_usage))
```

Use a time series aggregation function directly in `STATS`.

```esql
TS metrics
| WHERE TRANGE(1 day)
| STATS RATE(search_requests) BY TBUCKET(1 hour)
```

Use `SUM` as the outer aggregation to sum counter rates across hosts.

```esql
TS metrics | STATS SUM(RATE(search_requests)) BY host
```

Use `AVG_OVER_TIME` to compute per-time-series averages, then sum by host and time bucket.

```esql
TS metrics
| WHERE @timestamp >= now() - 1 day
| STATS SUM(AVG_OVER_TIME(memory_usage)) BY host, TBUCKET(1 hour)
```

Compute per-minute rates per cluster, then derive 95th-percentile rate, peak rate, and headroom.

```esql
TS k8s
| WHERE @timestamp >= now() - 1 hour
| STATS rate = MAX(RATE(network.total_bytes_in)) BY cluster, TBUCKET(1 minute)
| STATS p95 = PERCENTILE(rate, 95), peak = MAX(rate) BY cluster
| EVAL headroom = peak - p95
| SORT headroom DESC
```

Group bare time series aggregation results by all dimensions implicitly.

```esql
TS k8s
| STATS avg = avg_over_time(network.cost)
| SORT avg DESC
```

Exclude the `pod` dimension from time series grouping with `WITHOUT`.

```esql
TS k8s
| STATS total_cost = sum(network.cost) BY WITHOUT(pod)
| SORT total_cost
```

Combine `WITHOUT` with `TBUCKET` for per-interval aggregates across the remaining dimensions.

```esql
TS k8s
| STATS total_cost = sum(network.cost) BY WITHOUT(pod), tbucket = TBUCKET(1 hour)
| SORT total_cost
```

Show an invalid nested time series aggregation function query.

```esql
TS metrics | STATS AVG_OVER_TIME(RATE(memory_usage))
```

## Limitations

- `COUNT(*)` under `TS` does not count raw metric documents after the first `STATS`; use `COUNT(<field>)` or `COUNT_OVER_TIME()` against a named field to count samples for a specific metric.
- Commands that change row order, such as `SORT` or `FORK`, cannot appear between `TS` and the first `STATS`.
- Time series aggregation functions enforce the field’s `metric_type` mapping. For example, `RATE()` requires a counter and rejects gauge fields.
- Using a time series aggregation function in combination with an inner time series function causes an error.
- When combining a bare time series function with other groupings, only grouping functions such as `TBUCKET` or `WITHOUT` are allowed in the `BY` clause.
- `WITHOUT` can only be used inside the first `STATS` command under a `TS` source.
- Time series aggregations can produce large result sets, especially with many dimensions and small time buckets. The default result truncation size is increased to 10,000 rows.
