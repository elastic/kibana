# TS

The `TS` source command targets time series indices and enables time series aggregation functions inside the `STATS` command.

## Syntax

`TS index_pattern [METADATA fields]`

### Parameters

#### `index_pattern`

A list of indices, data streams, or aliases. Supports wildcards and date math.

#### `fields`

Optional.

A comma-separated list of metadata fields to retrieve.

## Examples

Calculate the total rate of search requests per host and hour.

```esql
TS metrics
  | WHERE @timestamp >= now() - 1 hour
  | STATS SUM(RATE(search_requests)) BY TBUCKET(1 hour), host
```

Return the average of the last memory usage values per time series using implicit `LAST_OVER_TIME()`.

```esql
TS metrics | STATS AVG(memory_usage)

TS metrics | STATS AVG(LAST_OVER_TIME(memory_usage))
```

Calculate the average memory usage across per-time-series averages.

```esql
TS metrics | STATS AVG(AVG_OVER_TIME(memory_usage))
```

Use a time series aggregation function directly in `STATS`.

```esql
TS metrics
| WHERE TRANGE(1 day)
| STATS RATE(search_requests) BY TBUCKET(1 hour)
```

Use `SUM` as the outer aggregation to sum counter rates across hosts.

```esql
TS metrics | STATS SUM(RATE(search_requests)) BY host
```

Use `AVG_OVER_TIME` to compute per-time-series averages, then group the results by host and time bucket.

```esql
TS metrics
| WHERE @timestamp >= now() - 1 day
| STATS SUM(AVG_OVER_TIME(memory_usage)) BY host, TBUCKET(1 hour)
```

Compute per-minute network rates per cluster, then derive percentile, peak, and headroom metrics.

```esql
TS k8s
| WHERE @timestamp >= now() - 1 hour
| STATS rate = MAX(RATE(network.total_bytes_in)) BY cluster, TBUCKET(1 minute)
| STATS p95 = PERCENTILE(rate, 95), peak = MAX(rate) BY cluster
| EVAL headroom = peak - p95
| SORT headroom DESC
```

Group bare time series aggregation results by all dimensions implicitly.

```esql
TS k8s
| STATS avg = avg_over_time(network.cost)
| SORT avg DESC
```

Use `WITHOUT` to group by every dimension except `pod`.

```esql
TS k8s
| STATS total_cost = sum(network.cost) BY WITHOUT(pod)
| SORT total_cost
```

15.875 | {"cluster":"staging","region":"us"}
18.625 | {"cluster":"prod","region":["eu","us"]}
26.5 | {"cluster":"qa"}

Combine `WITHOUT` with `TBUCKET` to group by surviving dimensions and time bucket.

```esql
TS k8s
| STATS total_cost = sum(network.cost) BY WITHOUT(pod), tbucket = TBUCKET(1 hour)
| SORT total_cost
```

Calculate garbage collection event count, average duration, and 99th-percentile duration from histogram metrics.

```esql
TS metrics-*
| WHERE TRANGE(1 hour)
| STATS count = COUNT(jvm.gc.duration),
        avg = AVG(jvm.gc.duration),
        p99 = PERCENTILE(jvm.gc.duration, 99)
  BY jvm.gc.action, TBUCKET(5 minutes)
```

Use `RATE()` instead of summing raw counter values.

```esql
TS metrics | STATS SUM(RATE(request_count)) BY host
```

Use `AVG_OVER_TIME` to avoid weighting time series with more frequent samples more heavily.

```esql
TS metrics
| STATS AVG(AVG_OVER_TIME(cpu_usage)) BY cluster, TBUCKET(1 minute)
```

Using a time series aggregation function in combination with an inner time series function causes an error.

```esql
TS metrics | STATS AVG_OVER_TIME(RATE(memory_usage))
```

## Limitations

- `TS` targets only time series indices.
- `COUNT(*)` under `TS` counts grouped rows after the first `STATS`, not raw metric documents. To count samples for a specific metric, use `COUNT(<field>)` or `COUNT_OVER_TIME()` against a named field.
- Commands that change row order, such as `SORT` or `FORK`, cannot appear between `TS` and the first `STATS`. After the first `STATS`, these commands are available again.
- Time series aggregation functions enforce the field’s `metric_type` mapping. For example, `RATE()` requires a counter and rejects gauge fields.
- A time series aggregation function cannot be combined with an inner time series aggregation function.
- `WITHOUT` can only be used inside the first `STATS` command under a `TS` source.
- When combining a bare time series function with other groupings, only grouping functions such as `TBUCKET` or `WITHOUT` are allowed in the `BY` clause. Bare dimension columns are not allowed.
