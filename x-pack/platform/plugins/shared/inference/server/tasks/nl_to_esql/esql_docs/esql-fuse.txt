# FUSE

The `FUSE` processing command merges rows from multiple result sets and assigns new relevance scores. It enables hybrid search by combining and scoring results from multiple queries together with the `FORK` command.

`FUSE` works by merging rows with matching `<key_columns>` values, then assigning new relevance scores using the specified `<fuse_method>` algorithm and the values from the `<group_column>` and `<score_column>`.

## Syntax

Use default parameters:

`FUSE`

Specify custom parameters:

`FUSE <fuse_method> SCORE BY <score_column> GROUP BY <group_column> KEY BY <key_columns> WITH <options>`

### Parameters

#### `fuse_method`

Optional. Defaults to `RRF`. Can be one of `RRF` for Reciprocal Rank Fusion or `LINEAR` for linear combination of scores. Designates which method to use to assign new relevance scores.

#### `options`

Optional. Options for the `fuse_method`.

#### `rank_constant`

Optional. Defaults to `60`. When `fuse_method` is `RRF`, represents the `rank_constant` used in the RRF formula.

#### `weights`

Optional. Defaults to `{}`. Allows you to set different weights for RRF or linear scores based on `group_column` values.

#### `normalizer`

Optional. Defaults to `none`. When `fuse_method` is `LINEAR`, can be one of `none` or `minmax`. Specifies which score normalization method to apply.

#### `score_column`

Optional. Defaults to `_score`. Designates which column to use to retrieve the relevance scores of the input row and where to output the new relevance scores of the merged rows.

#### `group_column`

Optional. Defaults to `_fork`. Designates which column represents the result set.

#### `key_columns`

Optional. Defaults to `_id, _index`. Rows with matching `key_columns` values are merged. Each remaining column value of the merged row is the first non-null value across the fork branches, or null in the absence of a value.

## Examples

Run lexical and semantic queries in parallel with `FORK`, then merge ranked results with default `RRF` fusion:

```esql
FROM books METADATA _id, _index, _score 
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE 
| SORT _score DESC
```

Run lexical and semantic queries in parallel, then merge ranked results with linear score combination:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR 
| SORT _score DESC
```

Normalize semantic and lexical scores with `minmax` before combining rows:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR WITH { "normalizer": "minmax" } 
| SORT _score DESC
```

Set custom branch weights to control lexical and semantic result importance:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR WITH { "weights": { "fork1": 0.7, "fork2": 0.3 }, "normalizer": "minmax" } 
| SORT _score DESC
```

Normalize scores and apply a minimum score cutoff to filter low-quality results:

```esql
FROM books METADATA _id, _index, _score
| WHERE title:"Shakespeare"
| SORT _score DESC
| LIMIT 100
| EVAL label = "semantic_results"
| FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
| WHERE _score > 0.1
| SORT _score DESC
```

Normalize scores in each `FORK` branch, filter irrelevant results, then merge with `RRF`:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare"
        | SORT _score DESC
        | LIMIT 100
        | EVAL label = "lexical"
        | FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
        | WHERE _score > 0.1
        | SORT _score DESC
        | LIMIT 100)
       (WHERE semantic_title:"Shakespeare"
       | SORT _score DESC
       | LIMIT 100
       | FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
       | WHERE _score > 0.1
       | SORT _score DESC
       | LIMIT 100)
| FUSE RRF
| SORT _score DESC
```

## Limitations

A `LIMIT` is required before `FUSE`, because `FUSE` can only work with a finite set of rows.

In Elastic Cloud Serverless and Elastic Stack 9.4 and later, `FORK` branches do not have an implicit `LIMIT 1000`. When using `FUSE` after `FORK`, a `LIMIT` must be added to each `FORK` branch.

In Elastic Stack 9.1 to 9.3, an implicit `LIMIT 1000` is added to each `FORK` branch. As a best practice and to avoid issues when upgrading to newer versions, add an explicit `LIMIT` before `FUSE`.

Columns of type `aggregate_metric_double`, `histogram`, and `date_range` are not yet supported and must be dropped using `DROP` before `FUSE`.

These limitations can be present either when `FUSE` is not combined with `FORK` or when `FUSE` doesn't use the default metadata columns `_id`, `_index`, `_score`, and `_fork`:

- `FUSE` assumes that `key_columns` are single valued. When `key_columns` are multivalued, `FUSE` can produce unreliable relevance scores.
- `FUSE` automatically assigns a score value of `NULL` if the `<score_column>` or `<group_column>` are multivalued.
- `FUSE` assumes that the combination of `key_columns` and `group_column` is unique. If not, `FUSE` can produce unreliable relevance scores.
