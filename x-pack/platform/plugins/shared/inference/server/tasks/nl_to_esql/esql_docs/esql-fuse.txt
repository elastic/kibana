# FUSE

The `FUSE` processing command merges rows from multiple result sets and assigns new relevance scores. It supports hybrid search with `FORK` by merging rows with matching key column values and rescoring them with the configured fusion method, group column, and score column.

`FUSE` can also normalize scores, making it simple to apply a minimum score cutoff and filter out low-quality results.

## Syntax

Use default parameters:

`FUSE`

Specify custom parameters:

`FUSE <fuse_method> SCORE BY <score_column> GROUP BY <group_column> KEY BY <key_columns> WITH <options>`

### Parameters

#### `fuse_method`

Optional. Defaults to `RRF`. Can be one of `RRF`, for Reciprocal Rank Fusion, or `LINEAR`, for linear combination of scores.

Designates which method to use to assign new relevance scores.

#### `score_column`

Optional. Defaults to `_score`.

Designates which column to use to retrieve the relevance scores of the input row and where to output the new relevance scores of the merged rows.

#### `group_column`

Optional. Defaults to `_fork`.

Designates which column represents the result set.

#### `key_columns`

Optional. Defaults to `_id, _index`.

Rows with matching `key_columns` values are merged. Each remaining column value of the merged row is the first non-null value across the fork branches, or null in the absence of a value.

#### `options`

Optional.

Options for the `fuse_method`.

#### `rank_constant`

Optional. Defaults to `60`.

When `fuse_method` is `RRF`, represents the `rank_constant` used in the RRF formula.

#### `normalizer`

Optional. Defaults to `none`. Can be one of `none` or `minmax`.

When `fuse_method` is `LINEAR`, specifies which score normalization method to apply.

#### `weights`

Optional. Defaults to `{}`.

Allows you to set different weights for RRF scores or linear scores based on `group_column` values.

## Examples

Runs lexical and semantic searches for “Shakespeare” in parallel, merges matching book results with default RRF scoring, and sorts them by the fused score:

```esql
FROM books METADATA _id, _index, _score 
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE 
| SORT _score DESC
```

Uses linear score combination to merge lexical and semantic search results for “Shakespeare” and rank the merged books by score:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR 
| SORT _score DESC
```

Normalizes lexical and semantic scores with min-max normalization before combining them linearly and sorting the merged results:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR WITH { "normalizer": "minmax" } 
| SORT _score DESC
```

Applies custom weights to favor one search branch over another when linearly combining normalized lexical and semantic scores:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
       (WHERE semantic_title:"Shakespeare" | SORT _score DESC | LIMIT 100) 
| FUSE LINEAR WITH { "weights": { "fork1": 0.7, "fork2": 0.3 }, "normalizer": "minmax" } 
| SORT _score DESC
```

Normalizes scores for a single result set, filters out results below a minimum fused score, and returns the remaining books sorted by relevance:

```esql
FROM books METADATA _id, _index, _score
| WHERE title:"Shakespeare"
| SORT _score DESC
| LIMIT 100
| EVAL label = "semantic_results"
| FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
| WHERE _score > 0.1
| SORT _score DESC
```

Normalizes and filters scores inside each search branch, then merges the remaining lexical and semantic results with RRF scoring:

```esql
FROM books METADATA _id, _index, _score
| FORK (WHERE title:"Shakespeare"
        | SORT _score DESC
        | LIMIT 100
        | EVAL label = "lexical"
        | FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
        | WHERE _score > 0.1
        | SORT _score DESC
        | LIMIT 100)
       (WHERE semantic_title:"Shakespeare"
       | SORT _score DESC
       | LIMIT 100
       | FUSE LINEAR GROUP BY label WITH { "normalizer": "minmax" }
       | WHERE _score > 0.1
       | SORT _score DESC
       | LIMIT 100)
| FUSE RRF
| SORT _score DESC
```

## Limitations

A `LIMIT` is required before `FUSE`, because `FUSE` can only work with a finite set of rows.

When using `FUSE` after `FORK`, a `LIMIT` must be added to each `FORK` branch in Elastic Cloud Serverless and Elastic Stack 9.4 and later. In Elastic Stack 9.1 to 9.3, an implicit `LIMIT 1000` is added to each `FORK` branch, but adding an explicit `LIMIT` before `FUSE` is still recommended.

Columns of type `aggregate_metric_double`, `histogram`, and `date_range` are not yet supported and must be dropped using `DROP` before `FUSE`.

These limitations can be present when `FUSE` is not combined with `FORK`, or when `FUSE` doesn't use the default metadata columns `_id`, `_index`, `_score`, and `_fork`:

1. `FUSE` assumes that `key_columns` are single valued. When `key_columns` are multivalued, `FUSE` can produce unreliable relevance scores.
2. `FUSE` automatically assigns a score value of `NULL` if the `<score_column>` or `<group_column>` are multivalued.
3. `FUSE` assumes that the combination of `key_columns` and `group_column` is unique. If not, `FUSE` can produce unreliable relevance scores.
