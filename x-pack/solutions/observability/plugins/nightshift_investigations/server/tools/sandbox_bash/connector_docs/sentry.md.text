# Sentry

Use for: searching and listing issues across projects, issue details and events, stack traces,
error trends and frequency, project and organization information.

## Authentication

Sentry needs a Sentry connector from `/workspace/connectors.md`; without one it is not reachable.
Pass its id as `connector_id`. For that single command only, the environment contains:

- `CONNECTOR_HEADER_AUTHORIZATION` — full `Authorization` header value (`Bearer <token>`)
- `CONNECTOR_CONFIG_ORGANIZATIONSLUG` — the organization slug
- `CONNECTOR_CONFIG_BASEURL` — API base URL including `/api/0`; unset means `https://sentry.io/api/0`
```bash
SENTRY="${CONNECTOR_CONFIG_BASEURL:-https://sentry.io/api/0}"
SENTRY="${SENTRY%/}"
ORG="$CONNECTOR_CONFIG_ORGANIZATIONSLUG"
curl --fail-with-body -sS --max-time 60 -H "Authorization: $CONNECTOR_HEADER_AUTHORIZATION" \
  "$SENTRY/organizations/$ORG/projects/"
```

Sentry is read-only for investigations: never resolve, assign, delete or comment on issues.
Record what should change as a proposal instead.

## Endpoints

All paths below are relative to `$SENTRY`.

| Operation | Endpoint |
|-----------|----------|
| List projects | `GET /organizations/$ORG/projects/` |
| List issues (all projects) | `GET /organizations/$ORG/issues/?query=…&start=…&end=…` |
| List issues for a project | `GET /projects/$ORG/<PROJECT_SLUG>/issues/?query=…&statsPeriod=24h` |
| Issue details | `GET /organizations/$ORG/issues/<ISSUE_ID>/` |
| Issue events with stack traces | `GET /organizations/$ORG/issues/<ISSUE_ID>/events/?full=true` |
| Latest event | `GET /organizations/$ORG/issues/<ISSUE_ID>/events/latest/` |
| Recommended event | `GET /organizations/$ORG/issues/<ISSUE_ID>/events/recommended/` |
| Issue hashes with events | `GET /organizations/$ORG/issues/<ISSUE_ID>/hashes/?full=true` |

Issue list parameters:

- `query` — search query (see below)
- `statsPeriod` — relative range such as `24h`, `7d`, `30d`; for an incident window prefer absolute
  `start` and `end` (ISO 8601)
- `limit` — results per page (max 100); follow the `Link` header (`rel="next"`, `results="true"`)
  for more

## Search query examples

- `is:unresolved` — unresolved issues
- `level:error` — error-level issues
- `environment:production` — one environment
- `release:1.2.3` — one release; compare issues first seen in the release deployed before onset
- `firstSeen:>2026-01-01T13:30:00` — issues that first appeared after a point in time
- `message:"NullReferenceException"` — message text
- Combine filters with spaces: `is:unresolved level:error environment:production`

## Response structure

- Issues include `id`, `title`, `culprit`, `level`, `status`, `count`, `firstSeen`, `lastSeen`.
- Events include an `entries` array with a `type` such as `exception` or `message`.
- Stack traces are in `entries[].data.values[].stacktrace.frames[]`; each frame has `filename`,
  `function`, `lineNo` and `context`. Frames are ordered oldest call first, so the crashing frame
  is last.
