Whole-map investigation launched from the APM service map page. Activates when an observability.service-map-context attachment is present — it carries the user's map view filters (environment, kuery, time range, service group, highlighted services), not data. Surveys all services in scope for problems: active alerts, violated or degrading SLOs, ML anomalies, high error rate or latency on connections, and isolated services with missing connections. Explains the architecture (entry points, hubs, datastores, external dependencies), renders a service-map attachment, and links to the most problematic services and their alerts. Do NOT use when observability.service is attached — defer to investigate-apm-service. Do NOT use when observability.alert is attached — defer to investigate-apm-alert. Do NOT use for plain requests to just show or render a service map without the context attachment — defer to service-map.
