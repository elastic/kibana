# [SLO] Unwrap the ES query inspection envelope in embeddables

## Summary
SLO server routes wrap their response in `{ _wrapped, _inspect }` (arrays) or `{ ..., _inspect }` (objects) whenever ES query inspection is active — i.e. Kibana dev mode or the `observability:enableInspectEsQueries` advanced setting. The main SLO app hides this by injecting an "unwrapping" `sloClient` into its context, but the dashboard embeddables inject the raw client, so hooks like `useFetchHistoricalSummary` receive the wrapper object instead of the expected payload. Because the value is a non-`undefined` object, the `= []` default doesn't protect it, and consumers such as `slo_overview.tsx` call `.find()` on a non-array and throw, leaving the panel unrendered. This extracts the unwrapping logic into a shared helper and applies it to all SLO embeddables and their configuration flyouts.

## Changes
- Add `createUnwrappingSloClient` helper that strips the `_wrapped` / `_inspect` inspection envelope from route responses.
- Apply it once in `register_embeddables.ts` so all embeddables (overview, alerts, error budget, burn rate) and their UI-action configuration flyouts get an unwrapping client.
- Refactor `get_lazy_with_context_providers.tsx` to reuse the helper instead of its inline copy.
- Add unit tests for the helper (wrapped array, `_inspect`-only object, idempotence, pass-through cases).
- Add a dedicated Scout UI test that renders a single SLO overview panel with `observability:enableInspectEsQueries` enabled, making the regression deterministic; the existing tests keep covering the default (inspection off) path.

## Manual testing
1. Start Kibana in dev mode (`yarn start`) — dev mode forces the inspection envelope on.
2. Create at least one SLO with data.
3. Open a dashboard, add a single "SLO Overview" panel and select the SLO.
4. Confirm the panel renders the SLO card with its historical SLI chart (before this change the panel stayed empty / failed to render).
5. Optionally repeat with `observability:enableInspectEsQueries` toggled in Advanced Settings on a non-dev build to confirm both on/off behave correctly.
