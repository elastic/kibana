# [Alerting V2] Redesign chat inline attachments for rules and action policies (#1042)

## Summary
Redesign the Agent Builder inline attachment cards for Alerting v2 rules and action policies so they match the new alerting flyout language (badges, tags, query blocks, info rows). The current cards are hand-rolled `EuiPanel`/`EuiBadge`/`EuiText` and reuse none of the flyout components. Draft / agent-assisted semantics must be preserved.

## Steps
1. Review the Figma design and the target structures in the issue; decide which pieces are shared between both cards (header with icon + name + Preview, footer info row).
2. Identify reusable flyout pieces (`ActionPolicyStateBadge`, `BadgeList`, `PopoverItems`, `MatcherSummary`, `definition_items`, `RULE_KIND_ICONS`, query preview/code block) and extract any that are flyout-private into shared components.
3. Rework `rule_inline_content.tsx` (simplified): header (rule icon + name + Preview), body (description + tags), footer info (Outcome | Status | Schedule), keeping draft status handling. Outcome is hardcoded to `alert` for now (see TODO).
4. (Optional) Extended rule variant: query code block with copy action. Only one variant (simplified or extended) is needed; no switching behavior.
5. Rework `action_policy_inline_content.tsx` (simplified): header (policy icon + name + Preview), body (policy scope: rule tags + advanced matching query, info tooltip), footer info (Status | Send data per | Frequency | Destination).
6. (Optional) Extended policy variant: description above the policy scope. Same as above: only one variant is needed.
7. Wire the Preview action and confirm canvas content and attachment definitions still work with the new cards.
8. Add i18n for new strings.
9. Update the existing Jest tests for both inline cards and add coverage for the extended variants and draft state.
10. Verify visually in Agent Builder chat against the Figma design.

## Files likely to change
- `x-pack/platform/plugins/shared/alerting_v2/public/agent_builder/attachments/rule_inline_content.tsx` — rule card redesign
- `x-pack/platform/plugins/shared/alerting_v2/public/agent_builder/attachments/action_policy_inline_content.tsx` — policy card redesign
- Matching `*.test.tsx` files for both inline cards
- `x-pack/platform/plugins/shared/alerting_v2/public/agent_builder/attachments/rule_attachment_definition.tsx` and `action_policy_attachment_definition.tsx` — only if the Preview or extended wiring needs it
- `x-pack/platform/plugins/shared/alerting_v2/public/components/` (`action_policy/`, `rule/rule_summary/`) — extracting or reusing shared badge, tag, info row and query pieces

## Decisions
- Simplified vs extended: either one is enough; the design has no switching behavior, so no prop/data/canvas toggle.
- Preview: keeps opening whatever it opens today (existing inline attachment behavior); no change.
- Shared pieces: import directly from flyout components when possible; decide on extraction case by case when reached.
