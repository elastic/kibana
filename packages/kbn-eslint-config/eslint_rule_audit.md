# Kibana ESLint rule audit for Oxlint 1.79

## Decision summary

This is a policy inventory, not a lint result. The authoritative static baseline contains **725 deliberate assignments** and **375 distinct deliberate rule IDs** across the root and shared Kibana configs. Every distinct ID appears exactly once in the complete table below. Generated `eslint-config-prettier` disables are counted separately.

| Recommendation | Rules | Meaning |
| --- | ---: | --- |
| `KEEP_ESLINT` | 139 | No pinned native rule preserves the deliberate policy; keep it in ESLint. |
| `MIGRATE_OXLINT` | 204 | A pinned native rule exists, its implementation covers the configured policy, and every static option/default can be preserved. |
| `REPLACE_ESLINT` | 13 | Current owner guidance or source-verified behavior provides a replacement; replace rather than carry the old rule forward. |
| `REMOVE` | 7 | Concrete owner, source, or effective-config evidence shows the deliberate assignment should be deleted. |
| `REVIEW` | 12 | A native route exists but configured options/defaults are incompatible or unverified, or a deprecated rule has no replacement. |
| **Total** | **375** | Reconciles to the deliberate distinct-rule baseline. |

The source-parity sweep finds **223 rows with an equivalent or reviewable registered native route**: 204 migrate, 7 replace, 11 review, and 1 remove-at-cutover helper. Two more replacement rows map to Oxlint's native `options.reportUnusedDisableDirectives` control rather than a rule ID. The remaining 150 rows are 139 keep, 4 owner-directed ESLint/plugin replacements with no equivalent pinned rule, 1 unsupported review, and 6 other removals. The repository currently activates **61** deliberate IDs in `.oxlintrc.json` or `.oxlint/*.jsonc`: 58 are clean migration candidates, 2 have option-parity gaps, and 1 is deprecated.

### Cleanup progress

The inventory and recommendation totals above remain the original point-in-time audit; they are not remaining-work counts. Source locations in the table are also from that snapshot.

PR [#288198](https://github.com/elastic/kibana/pull/288198) completes **7 of the 17** prioritized enabled-rule items below. Ten remain.

### Classification rules

- `MIGRATE_OXLINT` requires pinned support, source evidence for the relevant syntax, and preservation of **every** configured option and semantic default; a basename match is insufficient.
- `KEEP_ESLINT` does not mean “keep forever”; it means Oxlint 1.79 has no native implementation that preserves this policy.
- `REPLACE_ESLINT` requires an owner-directed replacement or a source-verified native equivalent. It is distinct from a straight same-policy migration.
- `REMOVE` is used only with concrete evidence: ESLint rejects `no-return-await`, jsx-a11y documents `no-onchange` as obsolete, `@typescript-eslint/no-undef` is not a rule, native `no-unused-vars` subsumes the JSX helper, and the final Prettier override makes three formatting assignments ineffective.
- `REVIEW` preserves uncertainty instead of silently weakening policy. Computed/spread options and known default mismatches are never called compatible.

### Replacement details that need policy mapping

- `no-empty-interface` → `no-empty-object-type`: the replacement additionally governs `{}` and exposes `allowInterfaces`/`allowObjectTypes`; see `node_modules/@typescript-eslint/eslint-plugin/dist/rules/no-empty-object-type.js:28-56`. Kibana currently sets the replacement `off` at `root:2396` and `ts:69`.
- `no-var-requires` → `no-require-imports`: the replacement checks all `require()` calls and TS import-equals, with `allow` and `allowAsImport`; see `node_modules/@typescript-eslint/eslint-plugin/dist/rules/no-require-imports.js:39-68`. Kibana currently sets it `off` at `root:2400`.
- ~~`prefer-ts-expect-error` → `ban-ts-comment`~~: completed in [#288198](https://github.com/elastic/kibana/pull/288198) with a scoped configuration that preserves the existing policy; see `node_modules/@typescript-eslint/eslint-plugin/dist/rules/ban-ts-comment.js:7-83`.
- `no-throw-literal` → `typescript/only-throw-error`: the replacement keeps the default allowances for `any`, `unknown`, and rethrows while using type information for other values. Pinned `oxlint` declares `oxlint-tsgolint` as an optional peer (`node_modules/oxlint/package.json:48-58`), and that peer is not installed.
- `no-process-exit`: ESLint directs users to `n/no-process-exit`, while pinned Oxlint exposes `unicorn/no-process-exit`. The [pinned Oxlint implementation](https://github.com/oxc-project/oxc/blob/oxlint_v1.79.0/crates/oxc_linter/src/rules/unicorn/no_process_exit.rs) exempts hashbangs, process event handlers, and worker-thread imports, so the equal basename is not sufficient evidence of behavioral parity.
