`@kbn/eslint-plugin-disable` provides custom rules to allow us to enforce specific eslint rules behaviours around eslint disables that we need to implement Bazel packages across the monorepo as our main development unit.

The rules run in Oxlint: `.oxlint/index.mts` loads `oxlint_plugin.js`, which registers `@kbn/swc-register` so Oxlint can load this TypeScript package. The rules use Oxlint's `createOnce` API and are wrapped with `eslintCompatPlugin`, so ESLint still resolves `@kbn/disable/*` names in disable comments. Both rules check `eslint-disable*` and `oxlint-disable*` comments.

Rule test cases live in `src/rules/*.cases.ts` and run through Oxlint's `RuleTester` from `src/rules/oxlint_rules.test.ts`.

## `@kbn/disable/no_naked_eslint_disable`

Disallows the usage of naked `eslint-disable*` and `oxlint-disable*` comments without being specific about each rule to disable.

## `@kbn/disable/no_protected_eslint_disable`

Disallows `eslint-disable*` and `oxlint-disable*` comments with specific protected rules that were built to not be disabled. Please contact the Kibana Operations team if you have a justifiable use case for disabling one of them.
